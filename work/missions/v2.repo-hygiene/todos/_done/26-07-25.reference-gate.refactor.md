### Why this is one order and not several

Four findings share one cause and one cure, and bundling them is what makes the cure *provable in a single diff*:

- The reference-integrity axis is doctrine with no owner — a grep recipe transcribed into `work/PROJECT.md`, which every consuming project must re-author. Charter amendment A1 calls that "prose without an owner", the failure this mission exists to kill.
- The sanctioned-absence set has **three homes** that already disagree, which is exactly the drift the axis is supposed to catch.
- The gate cannot become the axis's owner while the axis's own facts live in the recipe that the gate would replace.

Splitting them would leave a state where BASELINE, the declaration and the gate each hold a partial copy — the manufactured-divergence hazard Reconnaissance R2 warns about, in a new costume.

### The discrimination measurement — the engine's core rule

The researcher measured backtick/link-target membership against the real corpus, and it is **necessary but not sufficient**:

| Class | Real instances | Inside backticks or a link target? |
| --- | --- | --- |
| Extension-less prose (`work/README`) | 1 | No |
| Slash-separated word list (`…/docs/sessions`) | 1 | No |
| Deliberate illustrative (`src/lib/`, `docs/api/`) | 3 | **Yes — all** |
| Genuinely broken | 3 | **Mixed — 2 yes, 1 in YAML frontmatter** |

So: requiring a code span or link target kills both prose classes at zero cost, but it would *also* mask a real break sitting in a frontmatter field, and it cannot separate illustrative paths from real ones. The illustrative class carries its own declared remedy — the `<…>` placeholder convention the schema already defines and the current recipe already filters. Recommended shape, for the planner to accept or better: structured frontmatter fields are their own reference class, checked unconditionally; prose is checked only inside code spans and link targets; `<…>` placeholders are exempt by the existing rule.

### Phase 2 — Build the engine

`.claude/bin/reference-gate` (new), `.claude/bin/package.json`, `.claude/BASELINE.md` Tooling manifest bullet.

House style throughout. Parser reads the four subsections by verbatim heading string, first-code-span-is-the-path. Scan set is `git ls-files '*.md'` under declared roots minus exclusions — tracked-only by construction, which is what keeps gitignored scratch out without a special case.

Classification, in priority order: frontmatter path values are their own unconditionally-checked class (this catches the `depends-on:` list literal); body candidates only inside code spans and link targets, **left-boundary-anchored** (kills `/tmp/transcript` and `~/.claude/projects/`); full `git show <ref>:<path>` **and bare `<ref>:<path>`** both go to the provenance class, never live-tree extraction — the verified silent-false-negative killer; `<path>:<line>` citations strip the line number; `<…>` placeholders exempt; relative links skipped with a code comment marking the A4-8 seam.
