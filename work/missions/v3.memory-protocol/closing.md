## What the work system itself taught

**The gate stayed green while the canon broke — four times now, on four mechanisms.** The close's own reference sweep was the fourth: gate at 0 failures, six genuinely dangling links, every one file-relative without a scope-root prefix. It also found that the carried git bug holds **three** permanently-unresolvable v2-era pointers rather than the two the sweep order named — the third written in bare prose with no directory prefix, invisible to the gate by the other blind spot. Any future audit that trusts the gate's warning count is off by one there. Filing the two phase orders into `_done/` invalidated eleven relative link targets, and `reference-gate` reported 0 failures throughout: each link carries a correct backticked repo-root path as its *text*, which the gate extracts and resolves, and a broken relative *target*, which it skips. The trap `work/footguns/canon-references.md` documents fired on the campaign that was documenting it. The lesson has stopped being about this gate: **a green check is evidence only about what the check looks at**, and the cheapest way to be wrong is to hold two signals that agree because neither is watching.

**"Checked, not inferred" earned its sentence on its own author.** The protocol's single-process precondition says *never assume a reconnect replaced a server — count processes*. At the gate the operator reported believing the other sessions were already closed. They were not: six servers, each with a live parent, one per terminal tab. Only counting revealed it. A rule validated against the belief of the person who commissioned it is worth more than a rule validated against a test.

**Reconnaissance paid for itself four times before a line was built.** It found an acceptance criterion that was literally unsatisfiable (the inventory cited to a section that does not contain it); an acceptance grep that returned one hit and missed the other half of the pair it existed to verify; the ignored-content stranding trap that would have left the target repo dirty in a way `git status` cannot see; and — the expensive one — that the instinctive process-count command reads **0** against a ground truth of **6**, because Linux truncates the process name at fifteen characters. A run using it would have proceeded wedged, then read contention artifacts as falsified discriminants and manufactured a spurious failure verdict against the charter's own criterion. The mandatory gate is not ceremony.

**A returned verdict is a claim.** Both phases passed, and verifying them independently changed the record twice. Phase 1's "fourteenth fact" was **recovered** from a subagent transcript rather than conceded, turning a thirteen-vs-fourteen discrepancy into a documented sixteen-item union. Phase 2's decisive argument had a gap — it claimed no `Folder` nodes exist for directories the refactor created, but `shared/` has them — and checking the target repo's git history showed `shared/` *predates* the refactor, which made the partition exact and left the orphan-generation hypothesis the only one the evidence admits. The correction strengthened the conclusion; not checking would have shipped a weaker argument under a stronger claim.

**Constraints written into briefs have a shelf life.** This Executor carried `git diff <M1-close-sha> HEAD -- .claude/protocols/ empty` into a remediation brief *after* phase 2 had legitimately amended the protocol. The Manager caught it and re-baselined. A check pinned to a moving target silently inverts from a safeguard into a false alarm; pin the check to what it is actually protecting, not to the commit that happened to satisfy it once.

**A deferral is scoped to the conditions that produced it.** The role-card gating bug was correctly ruled out of phase 1's scope — inside this repo it is redundancy, not contradiction, because the evidence-passing rule degrades it gracefully. Then the operator chose to fold to `main`, which publishes those cards to every consuming repo, and the same finding stopped being cosmetic. The ruling had not been wrong; it had been *scoped*, and nobody re-read it when the scope changed. Asking "are these related to the recent work?" at the close is what surfaced it.

**The doctrine ran on itself before it shipped.** Every brief this campaign wrote carried the evidence-passing statement — *no verification, by declaration* — and every specialist fell back to grep accordingly. The protocol was load-bearing in its own construction, which is the cheapest possible integration test and the reason the role-card gap was felt rather than merely reasoned about: the Executor's own briefs had to override the researcher card explicitly.
