# Phase 1 — channel: hold-open mechanics and the read-only boundary

## Objective

Establish empirically whether a held-open `claude -p --input-format stream-json --output-format stream-json` process against a real large session is (a) a *session* — capturable id, live-appending transcript, resumable after its process dies — (b) an *observable* one, emitting a usable per-turn event wire, and (c) a *bounded* one, able to answer consults without acquiring the ability to act.

This phase carries both of the mission's refutation-shaped failure criteria. Its outcome gates phase 2: if live transcript append or the event stream cannot be demonstrated, or the read-only boundary cannot be held, the economics run never happens and the milestone escalates a refutation rather than working around it.

Rated `high` for planning difficulty: the stdin wire format is **undocumented** for the CLI (the Agent SDK's `SDKUserMessage` shape is the only published lead, and v2.1.220's own docs do not specify it), so a meaningful part of the phase is discovery whose result reshapes the rest of the work.

## Scope

### The harness

Build a spike harness at **`work/milestones/1.spike/harness/`** — the milestone directory, per the operator's ruling 4 (`MILESTONE.md` § Settled at planning). It is *mission apparatus*, committed so it archives with the mission and M2/M4 can reread it; it is deliberately **not** a `.claude/bin/` script, because M2 must design the product shape from the measurements rather than inherit the spike's expedient one. Raw stream logs are written to **`tmp/spike/`** — gitignored scratch, already declared for exactly this in `work/PROJECT.md` § Structure ("runtime stream logs"), and outside the reference gate's scope roots.

Construction notes, from the repo's existing tooling conventions and hazard ledger:

- Bun scripts, `#!/usr/bin/env bun`, resolving `repoRoot` via `git rev-parse --show-toplevel` — the pattern all four `.claude/bin/` scripts share. No-args prints a `usage:` line to stderr and exits 1.
- **Every `.claude/bin/`-style JSDoc header hazard applies**: a literal `*/` inside the opening comment block closes it early and bun refuses to parse the file (`.claude/ADR.md` § Standing hazards). Describe globs in prose.
- Unlike every existing script in this repo, the harness needs a **long-lived async `spawn`**, not `spawnSync` — holding stdin open across turns is the whole point. There is no in-repo precedent to copy; this is new ground.
- Tee the child's stdout verbatim to a log under `tmp/spike/` *before* parsing, so a parse failure never destroys the evidence.

### The test vehicle

Resume-**fork** this repo's largest local transcript into the held-open channel. Candidate at planning time: `76ba13c6-e6f5-4933-9e6c-7ef3fbdd6b7d` (6.2 MB, `~/.claude/projects/-home-yarrow-dev-claude-workflow/`, modified 26-07-27). The harness must **re-select at run time** — take the largest `.jsonl` in this repo's project-store directory, excluding the running session's own — because the local cache has a retention policy and the named candidate may be gone. Record the vehicle's id and byte size in the run log.

**`--fork-session` is mandatory and load-bearing.** Without it, resume continues the transcript *in place* and mutates a real session's recorded history (`work/README.md` § The callback grammar). The spike must never write into a transcript it did not create.

### The spawn construction

Mirror `.claude/bin/consult`'s five-layer read-only construction onto the streaming spawn — that script is the canonical statement of the boundary and the phase should not invent a second one:

1. `--settings` JSON carrying `permissions: { defaultMode: "dontAsk", deny: DENY }` **and** `disableAllHooks: true` (hooks run outside the permission layers; without this the repo's own Stop/SessionEnd hooks fire inside a supposedly read-only process)
2. `--strict-mcp-config --mcp-config '{"mcpServers":{}}'`
3. `--allowedTools Read,Grep,Glob`
4. `--disallowedTools <DENY>` — copy the DENY array from `consult` verbatim
5. `--permission-mode dontAsk`

Plus `--verbose` (the Executor's own stream-json recipe carries it — `.claude/agents/executor/CLAUDE.md`), and `--input-format stream-json --output-format stream-json`. Keep `consult`'s flag ordering discipline: the variadic list flags come before anything positional.

**Record, do not repair**, any drift found between `consult`'s DENY list and v2.1.220's actual deferred/built-in tool registry — the DENY list was audited against 2.1.197 and the version-drift hazard is already registered (`.claude/ADR.md` § Standing hazards). It is M2/M3's to reconcile; noting it here is the phase's contribution.

### What the phase must discover and write down

The wire format is the phase's real research content, and the answers change how phase 2 measures:

- The exact JSON object shape accepted on stdin for a user turn, and whether it must be newline-delimited.
- How a turn's completion is signalled on stdout — which event marks quiescence, so the harness knows when to send turn N+1.
- **Where `usage` actually rides.** Docs confirm it on the terminal `result` event; whether a *per-turn* `result` (or a `message_delta`-style event) is emitted inside a multi-turn streaming process is unverified. If usage arrives only once at process exit, phase 2's measurement route changes materially — state the route explicitly in the addendum.
- How the process terminates cleanly (EOF on stdin is the documented signal; confirm), and its exit code.

### Boundary probes

With the construction above applied, send the channel turns that attempt to act — at minimum one file write and one shell command — and record the refusals verbatim. Do **not** run an unconstrained comparison spawn; the boundary is verified by refusal, and an unbounded process resumed against a real transcript is exactly what the construction exists to prevent.

## Acceptance

Headlessly verifiable unless marked. The convergence target of one Manager session.

1. **The harness exists and runs.** `work/milestones/1.spike/harness/` holds a bun script that runs from the repo root; invoked with no arguments it prints usage to stderr and exits 1. A completed run leaves a raw stream log under `tmp/spike/`.
2. **Multi-turn hold-open is demonstrated.** One channel process accepted **≥3 successive user turns on one stdin without respawn**, each producing an assistant answer. The stdin message shape and the turn-completion signal are written down in the addendum, verbatim enough to reimplement from.
3. **The session id is captured** from the `system` / `init` event and recorded in the run log.
4. **Live transcript append is demonstrated *while the process is alive*.** Record the byte size and line count of `~/.claude/projects/<repo-slug>/<captured-id>.jsonl` after turn 1 and again after turn 2, both sampled **before** the process exits, and show growth between them. Sampling only at exit does not satisfy this criterion — the distinction is the whole point of D4's transcript half.
5. **The event wire is characterised.** The event types emitted across a full run are enumerated, and the location of `usage` (which event, which fields of `input_tokens` / `output_tokens` / `cache_read_input_tokens` / `cache_creation_input_tokens` are present) is stated as fact, including the negative case if per-turn usage is not emitted.
6. **Clean death and post-mortem resume.** After EOF the process exits; its exit code is recorded; then `claude -p --resume <captured-id> --fork-session …` from the repo root returns an answer that demonstrably references the channel conversation. The channel's transcript survives its process.
7. **The read-only boundary holds.** With the five-layer construction applied, the channel refused both a write attempt and a shell-command attempt; the refusals are recorded verbatim. Any DENY-list drift against v2.1.220 is recorded (not repaired).
8. **Surface visibility is recorded as a finding, not a gate** (operator ruling 1). The CLI half is headless-checkable: state whether the live channel session appears in `claude --resume`'s listing. **The Desktop-surface half is operator-gated** — the Executor stages it as a recipe for the operator to run and report, and does not stall on it.
9. **Findings appended to the evidence note** — a dated section in `work/notes/26-07-28.consult-token-cost-evidence.md` covering criteria 2–8, section-stamped per `work/README.md` § The callback grammar.
10. **The gate is called — operator-gated.** If criterion 4 (live append), criterion 5 (the event wire), or criterion 7 (the boundary) fails, the phase does **not** work around it: it stops, records the refuting evidence, and escalates. These are charter failure criteria 1 and 2, and a refutation here is a successful phase, not a failed one.
11. **No product changed.** `git status` shows no modification under `.claude/`.
