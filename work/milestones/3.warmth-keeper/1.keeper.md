# Phase 1 — keeper

## Objective

Build `.claude/bin/warmth-keeper` whole: the registry, the cadence, timeout-bounded beats issued through `.claude/bin/consult`, per-beat telemetry, and the self-managed cross-platform daemon that fires them. On landing, a superior handle can be held warm **by hand** — `warmth-keeper register <handle>` — which is what stops the token burn before phase 2 makes it automatic.

Rated `high` for planning difficulty: the cadence policy is novel, the process lifecycle has portability subtleties across three target platforms, and the failure semantics are load-bearing (a wedged scheduler is a worse outcome than no scheduler).

## Scope

**Files added** — `.claude/bin/warmth-keeper`, a bun script. Declared category: **the product** (`work/PROJECT.md` § Product / non-product boundary), under the sole sanctioned package root `.claude/bin/` (§ Package roots).

**Files edited, same commit** — `.claude/BASELINE.md` (manifest line 29 gains the script; root `CLAUDE.md` requires this in the same commit), `.claude/bin/package.json` (`bin` map), `work/PROJECT.md` (§ All roles quality-gate item 2 — the tooling smoke test lists `warmth-keeper`), and `.claude/bin/consult` (one field, below).

**Runtime state** — `~/.claude/warmth/`, created on demand. Not in the repo; mirrors `consult`'s existing `$HOME/.claude/projects/` precedent, so it adds no portability assumption `consult` does not already make.

### The command surface

Six subcommands. **These names are final** — phase 2 writes them verbatim into canon and three role cards.

| Command | Behavior |
| --- | --- |
| `register <handle>` | Create `~/.claude/warmth/<uuid>.json`. Idempotent: re-registering an existing handle refreshes its renewal clock rather than erroring. **Starts-or-attaches the daemon.** |
| `release <handle>` | Unlink the handle's file. If the registry is now empty, a running daemon exits within one beat interval. |
| `status` | Print the registry, each handle's last-beat time and outcome counters, and daemon liveness. |
| `tick` | One pass: read the registry, beat what is due, exit. Idempotent. |
| `watch` | Foreground loop — the daemon's own body, and the diagnostic path. |
| `stop` | Escape hatch: terminate the daemon, leaving the registry intact. |

No-arg invocation prints usage and exits 1, matching the convention the quality gate's tooling smoke test asserts for every `.claude/bin/` script.

### The registry — one file per handle

`~/.claude/warmth/<uuid>.json`. **Register creates, release unlinks, tick reads the directory.** No two sessions ever write the same byte, which *dissolves* the shared-mutable-store hazard (`.claude/ADR.md` § Standing hazards — "Multi-session soundness of shared mutable stores") rather than managing it as a third instance of that family. Record this reasoning in the script header; a later refactor to a single `registry.json` would silently join that family.

Each file carries at least: the full handle string, the parsed uuid, `registeredAt`, `renewedAt`, `lastBeatAt`, `lastOutcome`, `consecutiveFailures`, and cumulative outcome counters.

Alongside them: `daemon.pid` (`{pid, startToken, heartbeatAt}`) and a lock file. Both are daemon-owned, single-writer.

### Cadence — every default derives from a measurement

Each default is a flag override, and **each carries a comment citing its derivation** (the table in `MILESTONE.md` § The economics this milestone is built against):

| Default | Value | Derivation |
| --- | --- | --- |
| beat interval | **58 min** | every M1 cache write landed in `ephemeral_1h`; beat just under the window |
| dormancy bound | **18 h** | 4.262748 / 0.233411 = 18.26 beats per avoided cold reload × 58 min = 17.7 h |
| beat timeout | **180 s** | a cold beat on a large prefix pays full prefill; warm M1 turns ran 8–12 s |
| max consecutive failures | **3** | a handle whose transcript is gone must stop costing money |

**Dormancy is the orphan guard, and it is the reason it exists.** A registration is the activity window — the keeper beats while a handle is registered and does not attempt to observe consult traffic. A campaign that dies without releasing (five agent deaths in M2 make this a live case, not a hypothetical) would otherwise beat forever at roughly $5.60/day on a flagship prefix. Past the dormancy bound without renewal, a registration **lapses**: beating stops, the file stays for `status` to report, and a fresh `register` revives it. Past `maxConsecutiveFailures`, the same lapse applies.

### Beats

A beat is issued **through the instrument** — `.claude/bin/consult <handle> "<ping>" --usage-json` (D3: the fork ladder is the sole consult transport). The keeper **never spawns `claude` directly**; it has no second parser and no second boundary.

- **Timeout-bounded.** `spawnSync` carries `timeout` and `killSignal`. A hung beat is killed, recorded `timed_out`, and the tick proceeds to the next handle. Nothing wedges.
- **Failure is a returned state, never an exception.** On bun 1.3.14 `spawnSync` returns with `run.error` set and `status: 143` rather than throwing (M2 phase 1's correction to gate ruling 7). Handle `run.error`, `run.signal`, and a non-zero `run.status`; wrap in `try`/`catch` as well, but do not *rely* on the throw. No beat path may throw out of `tick`.
- **Never retry inside a window.** Any failure — rate limit included — defers to the next beat. A cadence-firing caller that tight-retries a rate limit converts an efficiency mechanism into a cost source and feeds the very limit it hit. The worst case is already bounded at one cold reload.
- **The ping is trivial.** A short fixed question; the answer is discarded. Only `--usage-json` and the exit code are read.

### Telemetry

Append one JSON object per beat to `~/.claude/warmth/telemetry.jsonl` (daemon-single-writer; the tick lock covers the manual case). Each record carries: ISO timestamp, handle, `outcome ∈ {ok, timed_out, failed, skipped, lapsed}`, `consult` exit code, trimmed `consult` stderr, wall-clock duration, and on success the full `--usage-json` object.

**This is the milestone's evidence surface**, and charter criterion 5 requires residual cold events to be *enumerable* — so the record must permit distinguishing a rate-limited beat from a plainly failed one after the fact.

### The one `consult` amendment

`consult --usage-json` gains **`rate_limit_events`**: the count of wire events with `type === "rate_limit_event"`, which M2 phase 1 found the wire carries and M1 never enumerated. A strict key addition to an existing JSON object — every existing key unchanged, no other `consult` behavior touched, no caller affected (all live call sites read stdout as prose). It reuses the existing `parseWire()` events array; no new parsing.

Without it the keeper cannot separate a rate-limited beat from a failed one, which is the design input the milestone stub records and which criterion 5's enumerability needs.

**Inherit the parser's posture.** M2's switch on event `type` is deliberately non-exhaustive, because the wire gains types without notice — `rate_limit_event` itself is one M1 never enumerated. Count by filtering for the type you want; never add an exhaustive switch, and never treat an unrecognized type as an error. The keeper reads only `--usage-json` and an exit code, so it inherits this tolerance for free — keep it that way.

### Daemon mechanics

- **Detach**: `spawn(process.execPath, [__filename, "watch", …], {detached: true, stdio: "ignore"}).unref()`. Portable across all three targets; `process.execPath` is the bun binary.
- **Single instance**: exclusive-create lock (`fs.openSync(path, "wx")`) — portable, no advisory-locking API needed.
- **Liveness**: `process.kill(pid, 0)` (a permission/existence probe on POSIX and Windows alike), *plus* a heartbeat mtime the daemon refreshes each loop. A pid that is live but whose heartbeat is older than 3× the beat interval is treated as dead — this is the pid-reuse guard, and `process.kill(pid, 0)` alone is not one.
- **Stale reap**: a lock whose owner fails either liveness test is reaped and taken over, never honored.
- **Self-exit**: an empty registry ends the loop.
- **No reboot survival, by design** — see `MILESTONE.md` § Scope.

## Acceptance

The literal convergence target of an autonomous Manager session.

1. `.claude/bin/warmth-keeper` exists, is executable, has a bun shebang, and opens with a JSDoc header containing **no literal `*/`** (`.claude/ADR.md` § Standing hazards — a glob written in prose closes the comment and bun then refuses to parse the file). Verify with `bun run .claude/bin/warmth-keeper`.
2. No-arg invocation prints usage and exits 1.
3. All six subcommands are implemented under exactly the names in § The command surface.
4. `register <handle>` creates exactly one file, `~/.claude/warmth/<uuid>.json`; re-registering the same handle does not error and advances `renewedAt`.
5. `release <handle>` unlinks that file and leaves every other handle's file untouched.
6. Grep proves one-file-per-handle: no code path opens a second handle's file for write, and there is no single shared registry file.
7. The four cadence defaults are 58 min / 18 h / 180 s / 3, each overridable by flag, and each carrying a source comment citing its derivation.
8. `tick` exits rather than looping; a handle not yet due is skipped **without spawning `consult`** — verify with a clock override and assert no child was spawned.
9. Beats are issued only through `.claude/bin/consult`. Grep proves the file never spawns `claude` directly.
10. A hung beat returns: with the consult path pointed at a sleep stub exceeding the timeout, `tick` records `timed_out` and completes. Assert `tick`'s own exit is timely and its exit code is 0.
11. No beat path throws out of `tick`: `run.error`, `run.signal`, and non-zero `run.status` are each handled as returned state (M2's bun finding). Verify by pointing the consult path at a stub that exits non-zero and one that is missing entirely.
12. A failing beat is **never retried inside the window** — assert exactly one `consult` spawn per due handle per `tick`, whatever the outcome.
13. Telemetry is appended as JSONL with the fields listed in § Telemetry, one object per beat, and every object parses.
14. `consult --usage-json` emits `rate_limit_events` as a number; all previously-emitted keys are byte-identical on an unchanged consult. No other `consult` behavior is modified — verify by diffing the file and confirming the change is confined to the usage-object construction.
15. Concurrent invocation is guarded: a second `tick` while one holds the lock exits without beating. A lock whose owner is dead, or whose heartbeat exceeds 3× the beat interval, is reaped and taken over.
16. `register` starts the daemon when absent and attaches when present; the daemon survives the parent's exit (verify: register, let the invoking shell exit, confirm the pid is still live and the heartbeat advances).
17. Releasing the last handle causes a running daemon to exit within one beat interval.
18. **Smoke test — the milestone's warmth evidence.** Register a **small archived handle** (never the 6 MB vehicle) with `--interval 60s`; observe **≥2 beats** in the telemetry; confirm beat #2 shows `cache_read_input_tokens > 0` and `cache_creation_input_tokens ≈ 0`. Release; confirm the daemon exits. **Paste the two raw telemetry records into the phase addendum** — this is acceptance evidence, not a log line.
19. The script header states the portability posture verbatim: written portable, **verified on Linux only**, Windows/macOS unverified, and cites the Windows `claude`-shim hazard (`work/notes/26-07-28.consult-token-cost-evidence.md` § Secondary finding).
20. The script header also records the one-file-per-handle rationale against the shared-store hazard, so a later consolidating refactor cannot make that mistake silently.
21. `.claude/BASELINE.md` manifest and `.claude/bin/package.json`'s `bin` map both carry the script, **in this phase's commit** (root `CLAUDE.md`: adding a bootstrap file updates BASELINE in the same commit).
22. `work/PROJECT.md` § All roles quality-gate item 2 lists `warmth-keeper` in the tooling smoke test.
23. **Genericity** — the acceptance test for any `.claude/` change (root `CLAUDE.md`): no repo-specific paths, no machine-specific facts, no assumption a fresh bootstrapped repo would not satisfy. Grep for `claude-workflow`, `yarrow`, `play`, and repo-relative `tmp/` and confirm none appear.
24. Quality gate: tooling smoke test green including the new script; `reference-gate check` adds **no new failures** beyond the nine pre-existing `herdr.md` ones.
