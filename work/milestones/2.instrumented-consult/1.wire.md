# Phase 1 — wire: read the event stream, report the cost

## Objective

Convert `.claude/bin/consult` from "capture stdout as an opaque string" to "parse the child's stream-json event wire," extracting both the answer and the per-consult `usage` — without changing what any existing caller sees on stdout.

Rated `medium`: the wire is fully mapped by M1 and the output contract is settled by operator ruling, so the design space is small — but the failure-detection rework is subtle, and four named traps sit directly on the path.

## Scope

### The change

Add `--output-format stream-json --verbose` to the command `consult` builds (`--verbose` accompanies `-p --output-format stream-json`; the Executor's own recipe carries it). Keep every existing flag, including `--model fable` and the five read-only layers, and keep the flag-ordering discipline — `--permission-mode` last, because the variadic list flags would otherwise swallow a trailing positional.

Parse the emitted events; take the answer from the terminal `result` event's `result` field; take `usage` from **`result.usage`**.

### The four traps — avoid by construction, not by vigilance

M1 established these as fact (`work/milestones/1.spike/1.channel.md` § Addendum). Each has a specific mitigation and the implementation must show it:

1. **`total_cost_usd` is cumulative per process.** Per-consult cost is a *delta*. A single-turn consult makes this trivially the whole value — but write the arithmetic as a delta anyway, so a future multi-turn caller does not silently inherit a wrong number.
2. **`system`/`init` re-fires once per turn**, not once per process. Anything keyed on "the init event" must not assume uniqueness.
3. **`assistant` events split one model call across content blocks**, so summing `assistant.message.usage` double-counts. Use `result.usage`; if per-assistant accounting is ever needed, de-duplicate by `message.id`.
4. **`usage.iterations[]` is not a per-call breakdown.** Do not treat it as one.

### The output contract — preserved exactly (operator ruling 1)

- **stdout**: the answer text, alone, exactly as today. No JSON, no prefix, no usage line. Existing callers — the Executor's escalation ladder among them — must keep working with no edit.
- **stderr**: a compact human-readable usage line (input, output, cache read, cache creation with its `ephemeral_5m`/`ephemeral_1h` split, and cost). stderr is already `inherit`-flavoured territory for this script's diagnostics.
- **`--usage-json`**: opt-in flag emitting the same numbers as a single machine-readable JSON object. Emit it on **stderr** too, so stdout stays the answer channel under every flag combination.
- **Emit, don't append** (operator ruling 2) — no file writes, no evidence-note append, no repo-specific paths.

### Failure detection — reworked, and this is the subtle part

Today `consult` treats **empty stdout** as "the resume produced no answer" and maps it to exit 3 so callers reach the documented degrade path. Under stream-json that heuristic is obsolete: the child emits events regardless, so stdout is no longer empty on failure.

Replace it with event-stream evidence: a run is a failure when no terminal `result` event arrives, or when one arrives with an error subtype. Preserve the **existing exit-code contract** — `0` ran or dry, `1` usage/unparseable handle, `2` cross-machine (deferred), `3` transcript unusable (absent, or the fork produced no answer), `4` repo mismatch — because callers and the canon depend on those meanings. The mapping changes; the contract does not.

Also revisit `maxBuffer` (64 MB today): stream-json is more verbose than plain text for the same answer, and the existing comment notes that exceeding it errors rather than silently truncating. Keep that property.

### Oversized answers — path-as-message, as documented fallback

For an answer beyond a stated size threshold, write it to a file and return the path instead, with the threshold and the behaviour documented. **Fallback, never default** — the herdr citation frames it exactly that way, and a tool that silently returns paths instead of answers would break the caller contract ruling 1 exists to protect.

### `--dry` keeps working

It prints the fully-quoted command that *would* run; it must print the new array, including the stream-json flags.

### Where artifacts land

Edits `.claude/bin/consult` in place — the sole sanctioned package root (`work/PROJECT.md` § Package roots), already BASELINE-manifested. No new files. If the argument surface changes materially, `.claude/BASELINE.md`'s bin description is updated in the same commit per the repo's standing convention.

## Acceptance

Headlessly verifiable.

1. **`consult --dry <handle>` prints a command array containing `--output-format stream-json` and `--verbose`**, with `--permission-mode` still last and `--model fable` still present, and exits 0.
2. **A real consult round trip against a small archived handle returns its answer on stdout and nothing else** — stdout captured alone is byte-identical in kind to today's behaviour (answer text, no JSON envelope, no usage line).
3. **The same run emits usage on stderr**, carrying `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, the nested `cache_creation` TTL split, and a cost figure.
4. **`--usage-json` emits one valid JSON object** with those same fields, on stderr, leaving stdout still answer-only. Verified by piping stdout and stderr separately and parsing the latter with `jq`.
5. **Cost is computed as a delta, not the cumulative process total** — evidenced in the code and stated in the work doc, per trap 1.
6. **The four traps are each addressed in code with a comment naming the trap** — an auditor can find all four without reading M1.
7. **Exit codes preserved**: no args → usage on stderr, exit 1; unparseable handle → exit 1; a handle absent from both local cache and archive → exit 3; a handle whose transcript `cwd` is another repo → exit 4. Each demonstrated.
8. **Failure detection no longer rests on empty stdout** — the implementation keys on the terminal `result` event's presence and subtype; stated in the work doc.
9. **The oversized-answer fallback exists, is threshold-driven, and is documented as a fallback**, with the threshold stated.
10. **Genericity** — no repo-specific path, machine name, or project fact enters the script. It would run verbatim in a fresh consuming repo.
11. **Tooling smoke test passes** — `bun .claude/bin/consult` with no args prints usage and exits 1, per `work/PROJECT.md` § All roles.

## Depends on

Nothing within M2 — this is its first phase.

- **Assumed**: M1's wire map is accurate (`result.usage` carries the token fields; the terminal `result` event marks completion). If a real round trip contradicts it, that is a finding to record, not a discrepancy to paper over.
- **Left true for phase 2**: a working event parser inside `consult` that phase 2's boundary guard reads rather than reimplementing, and an established convention for where diagnostics go (stderr) that the guard's warning follows.
