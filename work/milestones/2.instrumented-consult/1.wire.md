# Phase 1 — wire: read the event stream, report the cost

## Objective

Convert `.claude/bin/consult` from "capture stdout as an opaque string" to "parse the child's stream-json event wire," extracting both the answer and the per-consult `usage` — without changing what any existing caller sees on stdout.

Rated `medium`: the wire is fully mapped by M1 and the output contract is settled by operator ruling, so the design space is small — but the failure-detection rework is subtle, and four named traps sit directly on the path.

## Scope

### The change

Add `--output-format stream-json --verbose` to the command `consult` builds (`--verbose` accompanies `-p --output-format stream-json`; the Executor's own recipe carries it). Keep every existing flag, including `--model fable` and the five read-only layers, and keep the flag-ordering discipline — `--permission-mode` last, because the variadic list flags would otherwise swallow a trailing positional.

Parse the emitted events; take the answer from the terminal `result` event's `result` field; take `usage` from **`result.usage`**.

### The four traps — avoid by construction, not by vigilance

M1 established these as fact (`work/milestones/1.spike/1.channel.md` § Addendum). Each has a specific mitigation and the implementation must show it:

1. **`total_cost_usd` is cumulative per process.** Per-consult cost is a *delta*. A single-turn consult makes this trivially the whole value — but write the arithmetic as a delta anyway, so a future multi-turn caller does not silently inherit a wrong number.
2. **`system`/`init` re-fires once per turn**, not once per process. Anything keyed on "the init event" must not assume uniqueness.
3. **`assistant` events split one model call across content blocks**, so summing `assistant.message.usage` double-counts. Use `result.usage`; if per-assistant accounting is ever needed, de-duplicate by `message.id`.
4. **`usage.iterations[]` is not a per-call breakdown.** Do not treat it as one.

### The output contract — preserved exactly (operator ruling 1)

- **stdout**: the answer text, alone, exactly as today. No JSON, no prefix, no usage line. Existing callers — the Executor's escalation ladder among them — must keep working with no edit.
- **stderr**: a compact human-readable usage line (input, output, cache read, cache creation with its `ephemeral_5m`/`ephemeral_1h` split, and cost). stderr is already `inherit`-flavoured territory for this script's diagnostics.
- **`--usage-json`**: opt-in flag emitting the same numbers as a single machine-readable JSON object. Emit it on **stderr** too, so stdout stays the answer channel under every flag combination.
- **Emit, don't append** (operator ruling 2) — no file writes, no evidence-note append, no repo-specific paths.

### Failure detection — reworked, and this is the subtle part

Today `consult` treats **empty stdout** as "the resume produced no answer" and maps it to exit 3 so callers reach the documented degrade path. Under stream-json that heuristic is obsolete: the child emits events regardless, so stdout is no longer empty on failure.

Replace it with event-stream evidence: a run is a failure when no terminal `result` event arrives, or when one arrives with an error subtype. Preserve the **existing exit-code contract** — `0` ran or dry, `1` usage/unparseable handle, `2` cross-machine (deferred), `3` transcript unusable (absent, or the fork produced no answer), `4` repo mismatch — because callers and the canon depend on those meanings. The mapping changes; the contract does not.

Also revisit `maxBuffer` (64 MB today): stream-json is more verbose than plain text for the same answer, and the existing comment notes that exceeding it errors rather than silently truncating. Keep that property.

### Oversized answers — path-as-message, as documented fallback

For an answer beyond a stated size threshold, write it to a file and return the path instead, with the threshold and the behaviour documented. **Fallback, never default** — the herdr citation frames it exactly that way, and a tool that silently returns paths instead of answers would break the caller contract ruling 1 exists to protect.

### `--dry` keeps working

It prints the fully-quoted command that *would* run; it must print the new array, including the stream-json flags.

### Where artifacts land

Edits `.claude/bin/consult` in place — the sole sanctioned package root (`work/PROJECT.md` § Package roots), already BASELINE-manifested. No new files. If the argument surface changes materially, `.claude/BASELINE.md`'s bin description is updated in the same commit per the repo's standing convention.

### Hardened at the Reconnaissance gate (26-07-29) — settled, not open

1. **Correction to this doc**: "Emit, don't append" above means **no auto-append of usage to the evidence note, and no repo-specific paths**. It does *not* forbid file writes in general — the oversized-answer fallback necessarily writes one. The two paragraphs are not in conflict; this sentence is what governs.
2. **The oversized-answer file goes to `os.tmpdir()`**, never a repo-relative path. `.claude/` is project-generic and must not assume a consuming repo declares a `tmp/` container — that lives in the `work/PROJECT.md` seam, which a fresh bootstrap does not have.
3. **The parser must retain the `tool_use_id` → tool-name mapping.** Phase 2's guard asks "did a tool *outside* the allowlist run successfully," but `tool_result` events carry only `tool_use_id` — the name lives on the originating `tool_use` block. Building the correlation here is a **phase 1 deliverable**; phase 2 consumes it and must not build a second parser.
4. **Probe before writing the failure branch.** Across M1's entire spike every `result` event carried `subtype: "success"` — including both refusals — so the error-subtype branch has *no* empirical basis, and what a nonexistent `--resume` id emits under stream-json is entirely unknown. Spend one throwaway probe (`claude -p --resume <bogus-uuid> --output-format stream-json --verbose`), record what it actually emits, and write the branch against observed behaviour. Shipping an untested branch in the phase's self-declared subtle part is the highest-risk shortcut available.
5. **Do not read `permission_denials` — at all.** It is a natural thing to reach for once parsing `result`, and M1 proved it reports `[]` across a session that genuinely refused two tools. A phase 1 that used it as a "ran cleanly" signal would silently reproduce the exact defect M2 exists to fix.
6. **`--usage-json` mirrors the raw field names verbatim** — `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, and nested `cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens`. No second vocabulary for a future reader to cross-reference.
7. **`maxBuffer` stays at 64 MB**, with a comment recording that it was re-examined and found adequate (stream-json's overhead is additive and bounded, not answer-length-multiplicative). **Add the missing guard**: the current code branches on `run.status !== 0` and never wraps `spawnSync`, but ENOBUFS may *throw* rather than set a status. Handle both, preserving the fail-loud property.
8. **Exit code 5 is reserved for phase 2** (`boundary violation detected; answer returned`). Phase 1 preserves 0/1/2/3/4 and leaves 5 unused; phase 2 documents it.
9. **Port, don't import, and don't copy the spawn machinery.** `work/milestones/1.spike/harness/channel.ts` parses this exact wire, but `work/` archives out of the tree while `.claude/bin/consult` must run in a bootstrapped copy that never had it — no import is possible. Hand-port the small parsing and trap logic with an attribution comment (mirroring how `channel.ts` cites `consult`). **Do not** copy its async `Bun.spawn` / held-open-stdin architecture: `consult` is single-shot, its `spawnSync` shape is structurally correct, and the async pumps exist to solve a deadlock class `consult` does not have.

## Acceptance

Headlessly verifiable.

1. **`consult --dry <handle>` prints a command array containing `--output-format stream-json` and `--verbose`**, with `--permission-mode` still last and `--model fable` still present, and exits 0.
2. **A real consult round trip against a small archived handle returns its answer on stdout and nothing else** — stdout captured alone is byte-identical in kind to today's behaviour (answer text, no JSON envelope, no usage line).
3. **The same run emits usage on stderr**, carrying `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, the nested `cache_creation` TTL split, and a cost figure.
4. **`--usage-json` emits one valid JSON object** with those same fields, on stderr, leaving stdout still answer-only. Verified by piping stdout and stderr separately and parsing the latter with `jq`.
5. **Cost is computed as a delta, not the cumulative process total** — evidenced in the code and stated in the work doc, per trap 1.
6. **The four traps are each addressed in code with a comment naming the trap** — an auditor can find all four without reading M1.
7. **Exit codes preserved**: no args → usage on stderr, exit 1; unparseable handle → exit 1; a handle absent from both local cache and archive → exit 3; a handle whose transcript `cwd` is another repo → exit 4. Each demonstrated.
8. **Failure detection no longer rests on empty stdout** — the implementation keys on the terminal `result` event's presence and subtype; stated in the work doc.
9. **The oversized-answer fallback exists, is threshold-driven, and is documented as a fallback**, with the threshold stated.
10. **Genericity** — no repo-specific path, machine name, or project fact enters the script. It would run verbatim in a fresh consuming repo.
11. **Tooling smoke test passes** — `bun .claude/bin/consult` with no args prints usage and exits 1, per `work/PROJECT.md` § All roles.
12. **The `tool_use_id` → tool-name mapping exists and is exposed** for phase 2's guard to consume — gate item 3. Demonstrated by showing the parser resolves a `tool_result` back to the name of the tool that produced it.
13. **The bogus-`--resume` probe ran and its output is recorded** — gate item 4. The failure branch cites what was observed, not what was assumed; if the probe shows an error subtype never occurs, the branch says so rather than coding an unreachable case silently.
14. **`permission_denials` appears nowhere in the phase's code** — gate item 5. Grep-verifiable.
15. **The ENOBUFS path is guarded** — gate item 7, covering both the throw and the status form, with the fail-loud property preserved.

## Depends on

Nothing within M2 — this is its first phase.

- **Assumed**: M1's wire map is accurate (`result.usage` carries the token fields; the terminal `result` event marks completion). If a real round trip contradicts it, that is a finding to record, not a discrepancy to paper over.
- **Left true for phase 2**: a working event parser inside `consult` that phase 2's boundary guard reads rather than reimplementing, and an established convention for where diagnostics go (stderr) that the guard's warning follows.

**Closed 26-07-29. All 15 acceptance criteria met.** `.claude/bin/consult` parses the stream-json event wire; `+270 / −39` on one file, no new tracked files, `.claude/BASELINE.md` correctly untouched (it enumerates no script's argument surface, so `--usage-json` triggers nothing).

**Gate item 4's probe overturned this doc's own premise — in the useful direction.** The phase doc recorded that "across M1's entire spike every `result` carried `subtype: 'success'`, so the error-subtype branch has *no* empirical basis." One throwaway probe settled it: a bogus `--resume` under stream-json exits 1, prints `No conversation found with session ID: <uuid>` on stderr, and emits **exactly one stdout line** — a terminal `result` with `subtype: "error_during_execution"`, `is_error: true`, and an `errors[]` array carrying the same text. The failure branch is therefore written against observed behaviour and is demonstrably reachable, not a defensively-coded unreachable case. Verbatim output: [`work/todos/_done/26-07-29.wire.md`](../../todos/_done/26-07-29.wire.md) § Research Findings.

**A correction to gate ruling 7.** It assumed ENOBUFS "may *throw* rather than set a status." On bun 1.3.14 it does neither exclusively — `spawnSync` returns normally with `error` set **and** `status: 143`. Both arms are guarded as directed, but it is the `run.error` check that actually catches it; the throw arm's handling was proved by injecting a synthetic throw, and ENOBUFS-as-a-throw was never observed on this runtime. Worth knowing before phase 2 relies on the same assumption.

**One event type M1 never enumerated**: `rate_limit_event`, observed in the happy-path stream (`system`/init → `assistant` → `rate_limit_event` → `result`). The parser retains unknown types and never switches exhaustively on `type` — phase 2 must keep that property.

**Left true for phase 2, as promised.** `parseWire()` returns `toolNames: Map<tool_use_id, name>` and `toolResults: [{tool_use_id, name, is_error}]`, built by walking **content blocks** on any event carrying an array `message.content` — deliberately not keyed on a carrier event type, since the carrier for `tool_result` was never empirically enumerated. Demonstrated live: a forced `Read` resolved as `tool_result toolu_01SnsBDbrMzLhRJ9r57pjchc → Read`. Phase 2's boundary guard consumes this and must not build a second parser. Diagnostics convention: stderr, with the usage render always the **last** stderr write — a guard warning must not displace it. Exit code 5 is unused and undocumented, as gate ruling 8 reserved.

**Blessing directive worth remembering at phase 2.** Acceptance 14's `permission_denials` prohibition covers **comments**, so the code may not cite the probe verbatim — the observed line contains the token. The rule that emerged: code cites the shape, the work doc holds the transcript.

**Economics datapoint, since it is this mission's subject.** Two identical one-word round trips against the same handle cost `$1.298` then `$0.079` — the first pays to build the `ephemeral_1h` cache (64,698 creation tokens), the second reads it (68,946 read tokens, 0 created). Roughly 16× cheaper inside the window, consistent with M1's ~18× warm/cold finding.
