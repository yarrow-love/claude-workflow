# Phase 2 — competency: the Janitor and the `/clean` verb

## Objective

Give repo hygiene an owner. Define the competency once, as a flat agent doc, and give the operator the on-demand verb — while making it explicit in both files that the verb is the *escape hatch*, not the habit.

## Scope

**1. `.claude/agents/janitor.md` — new, flat** (milestone P2; proposal-literal, no `workflows/` directory). House shape, per the staff exemplars (`reviewer.md`, `designer.md`): YAML frontmatter carrying only `name`, `description`, `model`; terse declarative prose; `## Role` → `## Project Supplement` → domain sections → `## Constraints`. It runs longer than the 40–46-line specialists because it carries real doctrine; keep it dense rather than expansive.

Content:

- **`## Role`** — staff authority, not executive: an inspector-general. Audits, routes, and gates; holds no campaign context; never performs structural surgery inline. Nearest kin is the Architect (advises, never dispatches builds); the reviewer is to code-correctness what the Janitor is to repo-structure.
- **The hat pattern** — the competency is *assumed by whichever session presides at a boundary*, not freshly dispatched. Carry the boundary table (blessing → Architect, lens depth · order close → Manager, light advisory checklist · milestone close → Executor, full blocking pass · on demand → `/clean`, authority mode). Fresh-session form exists only under `/clean`.
- **`## Project Supplement`** — read `work/PROJECT.md § Structure` (the declaration) before auditing anything; the axes are generic, every fact they test is the project's.
- **The five audit axes** — cite by the names phase 1 established in `work/README.md`; state for each what the pass *asks* and which part of the declaration answers it. Do not restate the doctrine phase 1 wrote.
- **The declaration-reading protocol** — what to do when the declaration is absent (a project that never authored § Structure), incomplete, or itself inconsistent with BASELINE's defaults. Absence is a finding, not a licence to invent an allowlist.
- **The three-rung remedy ladder**, with the threshold stated verbatim as resolved: rung 1 is *anything expressible as a move / rename / status-edit with zero judgment calls and a passing reference gate afterward* — applied inline, committed with enumerated paths. Rung 2 files a **typed remedy work order** flowing through normal blessing and execution. Rung 3 escalates the genuinely contestable (naming, boundary placement, relocation) to the operator; **in automatic mode an unresolved fork is an ESCALATE halt**, mirroring the Blessing gate.
- **Output convention** (milestone P9) — the pass invents no container: rung-1 fixes commit, rung-2 findings become `work/todos/` orders, rung-3 escalations are raised in-session. A pass run inside a campaign records itself in that campaign's own artifact.
- **`## Constraints`** — directs, never operates; never edits code to satisfy an axis; never overrules a declaration (a wrong declaration is a finding against the declaration, escalated, not silently corrected); read-only outside rung-1 mechanical fixes.

**2. `.claude/commands/clean.md` — new.** House shape for commands: no frontmatter, short prose, names the acting role by markdown link, handles `$ARGUMENTS` inline (empty = the whole repo), routes rather than inlining procedure. Authority mode, like `/design`: the main session IS the Janitor; judgment-closed.

It must state the **escape-hatch doctrine** (milestone P3) plainly: hygiene is codified within the normal workflow — the blessing lens, the order-close checklist, and the blocking milestone-close pass carry the load. Invoking `/clean` by hand is the remedy for a tree that drifted anyway, a rare outlier rather than habitual maintenance; a project needing it routinely has a gate that is not firing.

It states the composition: `/clean` **invokes** `/triage` as the work-tracking-fidelity axis (fork 3 resolution), runs the whole-canon reference-integrity axis, and adds the axis nothing else covers — source-tree structure against the declaration. Composition, not a fourth overlapping tool.

**3. Canon rows — `work/README.md`.** The role-ladder row (Janitor · staff — audits structure against the declaration; worn as a hat at boundaries, never dispatches) and the command-family row (`/clean [scope]` → Janitor · reconcile actual structure against the declaration; escape hatch, judgment-closed).

**4. Manifest — `.claude/BASELINE.md`.** Add `janitor.md` to the agents rows and `clean.md` to the commands row, **in the same commit that adds the files** (repo convention).

## Acceptance

1. `.claude/agents/janitor.md` exists with frontmatter carrying exactly `name`, `description`, `model` (matching the roster's convention), and contains: the role statement, the boundary/hat table with all four rows, the `## Project Supplement` pointer to `work/PROJECT.md § Structure`, the five audit axes by the names phase 1 established, the declaration-reading protocol including the absent-declaration case, the three-rung ladder with the zero-judgment threshold stated verbatim, the automatic-mode ESCALATE halt, the output convention, and `## Constraints`.
2. `.claude/commands/clean.md` exists, has no frontmatter, names the Janitor by markdown link to the agent doc, handles `$ARGUMENTS` with the empty case defined, states authority mode, and states the escape-hatch doctrine explicitly.
3. `clean.md` names the `/triage` composition and the whole-canon reference-integrity axis, and links `.claude/agents/manager/workflows/triage-todos.md` or `/triage` such that the reference resolves.
4. `work/README.md` § The role ladder has a Janitor row marked staff; § The command family has a `/clean` row.
5. `.claude/BASELINE.md` manifest lists `janitor.md` under agents and `clean.md` under commands; `git log` shows the manifest edit in the same commit as the file additions.
6. **Genericity (local check)**: neither new file contains a project-shaped fact; every project-specific input they need is described as read from `work/PROJECT.md § Structure`. Verify by the same grep as phase 1 plus a read-through.
7. The project quality gate passes, including reference resolution — both new paths resolve from every doc that cites them.
8. **Comprehension check**: a reader of `janitor.md` alone can classify a given finding into a rung and say what happens to it next.
