# Phase 4 — prove: the pass in anger, the mechanism, the enactment, the fold rehearsal

## Objective

Run the system against its own tree and let it find things. A hygiene system that cannot detect the divergences its predecessor already found has failed its acceptance (charter D6) — so the two seeded subjects are the honest test, and the pass must reach them by *auditing*, not by being told where to look.

This phase also lands the one piece of mechanism the mission acquired by amendment, files the enactment, and rehearses the fold.

## Scope

**1. The dogfood pass.** The Manager wears the janitor hat (milestone P3 — the hat pattern is the point; a fresh `/clean` dispatch is the escape hatch, not the mechanism under test) and runs the **full pass** against this tree. All five axes reported — each with a finding or an explicit *none found*; each finding rung-classified with its rationale recorded.

Expected subjects, neither of which may be short-circuited by prior knowledge — the record must show how the audit reached them:

- **Seeded divergence A** — `.claude/BASELINE.md:49` names three post-scaffold paths; the declaration authored in phase 1 names seven. A doctrine-consistency finding on the whole-canon reference-integrity axis, caught by *reading* (the mission architect's direction is explicit: the script is the durable prevention, not the detector). **Disposition**: unification into `work/PROJECT.md § Structure` as the single authoritative list, with BASELINE *referencing* the declaration rather than restating it. Classify the rung and justify it — the direction was pre-decided by the original bug filing, which is itself a fact the classification should weigh.
- **Seeded divergence B** — eight files (seven `.claude/` policy docs plus `work/footguns/README.md`) instruct roles to use or reconcile a footgun index in the root `CLAUDE.md`; this repo's root `CLAUDE.md` carries no such table (hazards moved to `.claude/ADR.md` § Standing hazards). The instructions remain *correct as generic convention* for a consuming repo — which is exactly what makes this contestable rather than mechanical. Expected rung 3: escalate the design question (should the template still model the ledger-index convention, or should the generic instructions stop presuming a table a purified template lacks?). Record the escalation and the operator's answer, or record it as raised-and-open.

**2. `.claude/bin/reference-gate` — the amended footprint** (milestone P6). Lands as a **typed rung-2 remedy work order** filed by the pass and executed under normal blessing — the pass's genuine rung-2 exercise. Design, as settled:

- Generic engine, zero project facts: it reads its sanctioned-absence list from `work/PROJECT.md § Structure`, not from its own source.
- Whole-canon scope (not `.claude/`-only), preserving the existing recipe's load-bearing behavior: `git show <ref>:<path>` expressions are consumed whole so tag-qualified paths are never extracted — **provenance data, not tree references**.
- House conventions for `bin/` scripts: bun, no-args prints usage and exits 1.
- BASELINE manifest row + a tooling smoke-test row in `work/PROJECT.md` § All roles item 2, landing with it.
- `work/PROJECT.md` quality-gate item 1 invokes the script instead of restating the grep — which is what leaves the sanctioned-absence set exactly one authoritative home.

**3. Enactment.** `work/proposals/26-07-25.repo-hygiene.md` → `work/proposals/_enacted/` with `status: enacted`, a `sessions:` stamp, and **reconciliation notes where the build diverged from the proposal**: at minimum the flat-`janitor.md` confirmation, the `.claude/bin/` footprint amendment, and the escape-hatch doctrine (which sharpens the proposal's framing of `/clean` from "on demand" to "remedy of last resort"). Per `work/proposals/README.md` — the closer of the enacting work files it.

**4. Fold preparation** (charter D5). Read the inherited runbook — `git show 26-07-23:work/missions/v1.subagent-boundary/runbooks/fold-and-close.md` — and rehearse against this mission's tree. **Derive the keep column from the specification, never from the tree**: BASELINE step 2's scaffold enumeration plus the manifest, transcribed, not grepped. The hard lesson is recorded in that runbook for a reason — the rehearsal-time tree lacks the mission archive that the ceremony-time tree will contain, and a tree-derived keep column silently smuggles archive into a purified `main`. This mission's new product files (`janitor.md`, `clean.md`, `reference-gate`) join the keep column **via BASELINE**, which is what makes the derivation catch them.

File the rehearsal record as a runbook in `work/runbooks/`. The `/close` ceremony itself is **out of scope and operator-only**.
