# The codebase-memory protocol — verified freshness, evidence-passing dispatch, and store-contention doctrine

> Proposal, 26-07-26, filed at operator direction from the v2 close review. Seeding evidence is empirical and foreign-repo: the `lasers` staleness incident and its upstream research (`~/dev/lasers/work/notes/26-07-25.codebase-memory-testing.md`) and the corrected operating runbook it produced (`~/dev/lasers/work/runbooks/codebase-memory.md`). Upstream: <https://github.com/DeusData/codebase-memory-mcp>, binary **0.9.0** at evidence time. This proposal is **not enacted in v2** — the operator ruled the mission closes first; the template folds with the defects named below intact, and this file is the successor's charter material.

## The problem

The template prescribes graph-first discovery for its read-heavy roles and trusts the index to be fresh. The `lasers` evidence shows that on 0.9.0 the freshness half of that bargain is not delivered: a graph reported itself current (`head_sha == HEAD`) while holding **1,010 nodes for a directory deleted in a committed refactor and zero for the directory the code moved to**. Every symptom traced to open, upstream-acknowledged defects — this is the tool's present design envelope, not a local misconfiguration.

Three findings, each contradicting a template prescription:

1. **Freshness cannot be inferred — only verified.** `head_sha` freezes at project-creation commit and never updates on re-index (upstream **#1213**, open, priority/high). The incremental watcher silently diverges from a clean rebuild and has no rename/move handling (**PR #1245**, unmerged; **#914**, silent `no_changes` no-op with new files on disk). The reliable checks are empirical: a **known-moved-path query flip** (`MATCH (n) WHERE n.file_path CONTAINS '<removed path>' RETURN count(n)` → 0; new path → >0) and **`expected_* == actual_*`** in the `index_repository` result. After any bulk move/rename, branch switch, or version bump the only correct action is a **full re-index at a committed checkpoint**.
2. **The supported multi-agent contract is orchestrator-verifies-then-passes-evidence.** Upstream's own multi-agent doctrine: the *parent* verifies index freshness and hands each subagent concrete evidence — project, qualified symbols, paths, call-chains, `check_index_coverage` results (whose clean result means "no recorded gap," never completeness). Subagents do **not** independently trust live graph queries. Our template ships the inverse.
3. **Per-session MCP servers are not deduplicated; concurrent sessions wedge the store.** Only the background daemon is a singleton; every client session spawns its own stdio server on the same SQLite store (**#277**, **#50/#185**; a `/mcp` reconnect *adds* a process). Concurrent holders block WAL checkpointing — observed: a 1.9 GB WAL against a 29 MB db — reads return a stale snapshot, re-index no-ops byte-identically, and `delete_project` fails (`Permission denied` on Windows). No compact/vacuum command exists in 0.9.0; recovery is kill-all processes → delete `<project>.db{,-shm,-wal}` → respawn one server → `index_repository(full)` → verify empirically.

## The remedy — four pillars

**P1 — Freshness is verified, never inferred.** Canon states the verification recipe once (a generic procedure home, product-side), and the graph-first role cards point at it: the known-moved-path flip, the `expected == actual` post-index gate, the full-re-index triggers (bulk move/rename, branch switch, binary upgrade, results contradicting a file), and the standing rule **when graph and file disagree, the file wins — re-index, then re-ask**. `head_sha`/`index_status` are named as non-signals.

**P2 — The dispatcher verifies; evidence rides the brief.** Adopt upstream's orchestrator-verifies-then-passes-evidence as dispatch doctrine: at recon/dispatch time the orchestrating role (Executor recon step, Manager briefs) verifies freshness **once** and passes concrete evidence into subagent briefs — project name, generation/verification result, qualified symbols, paths, coverage. Specialists treat the graph as pre-verified context, falling back to grep when the brief carries no verification. This composes with the dispatch-record convention (`work/todos/README.md` § Document structure): the verification evidence is brief content, recorded where dispatches are already recorded.

**P3 — Store contention is a standing hazard with a recovery runbook.** One `codebase-memory-mcp` process per store before any store operation or graph-dependent dispatch; a `.db-wal` far larger than its `.db` is the wedge canary; the kill-all → delete-store → single-server rebuild → verify sequence is the sanctioned recovery. This is the **same failure family as `work/todos/bugs/26-07-25.bug.concurrent-tree-commit-absorption.md`** — two authorized sessions sharing one mutable store (there the git index, here the SQLite graph) with no isolation — and the successor mission should treat them as one theme: multi-session soundness of shared mutable stores. Candidate home: `.claude/ADR.md` § Standing hazards (the portable statement) plus the generic procedure doc (the recovery).

**P4 — Version-robust authoring, per the D3 precedent.** The evidence base is 0.9.0; upstream's 0.9.1-rc milestone targets #1213 and PR #1245, so parts of this will be mooted. Author the doctrine against **observable discriminants** (the empirical checks of P1), never against version behavior; pin the evidence with a version ledger naming each reliance and its upstream issue, exactly as ADR D3 does for dispatch routing (`.claude/ADR.md`, Mission v2 — the version-pin ledger); on any binary upgrade, the ledger is the re-audit list.

What stays true and should not be weakened: the graph-first *economics*. Graph queries answering structure questions at a fraction of grep fan-out cost is the reason these prescriptions exist; the protocol adds verification, it does not retreat to grep.

## Enactment (26-07-27)

> Appended at the filing to `_enacted/` by `manager@play/a377b823-57a2-4f74-b03b-049170e6cef3`, mission v3.memory-protocol, M2 phase 2. **Nothing above this heading is altered** — the body stays in its own era's vocabulary, and the reconciliation between what it proposed and what landed is recorded here instead.

Where the build diverged from the text above, and why:

**The coverage tool named here is absent from the installed binary.** Finding 2 above names `check_index_coverage` results as one of the evidence items the orchestrator hands its subagents, and P2 carries them forward as "coverage". Authoring found the name nowhere in the installed binary's tool roster (`work/todos/_done/26-07-27.author.md` § I2, confirmed by the pre-authoring grep state in `work/todos/_done/26-07-27.execute-protocol.md` § Cross-phase findings, F6 — the name appeared at zero sites under `.claude/` too). Naming a tool that does not exist would reproduce the exact broken-truth defect the mission was chartered to end, so `.claude/protocols/codebase-graph.md` § Evidence-passing dispatch keeps the **semantics** and drops the **name**: coverage is listed as a brief item, and its meaning is stated as "a coverage check's clean result means *no recorded gap*, never completeness." The proposal's substance survives intact; only the tool name is gone. The same divergence is filed as note **N1** on the P4 version ledger in `.claude/ADR.md` (M2 phase 1), where it is explicitly *not* a version-pin row — coverage ships tool-nameless, so there is nothing for a roster change to flip. This note records the enactment side of the one finding, not a second finding.

**Serving-session verification scope was added beyond the four pillars.** P1 says freshness is verified after re-index; it does not say *where* the verification must run. Corroboration surfacing in the 48 hours after this proposal was filed — upstream #1296 and #1191, an MCP session serving a stale graph indefinitely after the watcher re-indexes — showed that a verification passing in one session says nothing about the session that will actually answer the queries. The charter absorbed it as an evidence delta (`work/MISSION.md` § the new-corroboration paragraph), and it landed as its own subsection, `.claude/protocols/codebase-graph.md` § "Verification is scoped to the serving session". This is an **addition** to P1, not a correction of it: the proposal's recipe is still the recipe, now with the scope its evidence base could not yet name.

**The A2 narrowing — the repo-local index path is an opt-in export mode, not the documented flow.** The proposal's site table treats `.claude/BASELINE.md`'s index bullet as wrong only in its recipe form and its `auto_index` freshness claim. Authoring found a third defect in the same bullet: it called "local, gitignored" *the index policy* when the default store resolves to the OS user-cache directory, entirely outside the repo. Investigation of the binary (`work/todos/_done/26-07-27.author.md` § I1) recovered an opt-in `persistence` parameter, default off, that writes a compressed repo-local artifact for team sharing — so a repo-local path is **real but never taken by the documented flow**. The landed wording states the store as out-of-repo, acknowledges the opt-in export mode by role rather than by parameter name, and restates the gitignore entry as defence-in-depth rather than as a description of where the index lives. `/initialize` check 7 keeps a real, if narrow, thing to audit. The escalation this could have triggered — drop the claim or re-scope the milestone — did not fire, because neither arm was reached.

**The site count: six proposed, nine rewired, and the charter numeral left alone.** § Where the template is wrong today names **six** sites. Milestone 1 closed against **nine**, and the ladder is recorded rather than smoothed: six here, **seven** at charter success criterion 3, **eight** when the manager card was added at milestone hardening, and **nine** when reconnaissance found `src/README.md:5` asserting the trust-the-index bargain verbatim in a bootstrap-copied scaffold file, outside every acceptance criterion (`work/todos/_done/26-07-27.execute-protocol.md` § Decisions — confirmed at the gate, C2). Two of the nine did not take the shape "rewrite the graph passage": **site 5** (`.claude/agents/manager/CLAUDE.md`) held **no graph text at all**, so it was *authored* — a new bullet under § Delegation Guidelines — rather than rewritten (§ Cross-phase findings, F3); **site 7** (root `README.md:20`) closed on a recorded **verified-no-change-needed** disposition, quote and reasoning kept, on the grounds that its parenthetical enumerates audit categories, names no signal, prescribes no tool, and sits in a file a consuming repo re-authors anyway (§ Per-phase readiness). The record's own summary is therefore "nine sites rewired — eight carrying the pointer, one carrying a recorded no-change disposition", and milestone acceptance 1 was met with that exception stated rather than resolved silently. The **charter's numeral was deliberately not rewritten**: the operative clause is the totality ("all … sites point at the protocol"), the numeral a charter-time enumeration snapshot, and close-out measures the totality — recorded with the milestone architect's attestation (`work/todos/_done/26-07-27.execute-protocol.md` § Decisions — confirmed at the gate, C3) instead of by editing the charter line. Nothing was dropped from the six: the same document's F4 full sweep found the proposal's table maps one-to-one onto the milestone's list, and no tenth site.

**Already reconciled, not a divergence — the doctrine home.** § The remedy P1 offered "a generic procedure home, product-side" and P3 named `.claude/ADR.md` § Standing hazards as a *candidate*. The operator named `.claude/protocols/` at charter, and `work/MISSION.md` **D2** records it as a determination founding a new manifested product class (cross-agent operational protocols). The proposal proposed a candidate; the charter chose. That is the adoption machinery working as designed, so it is filed here for completeness rather than as a place where the build departed from the spec — the ADR still carries the P3 standing-hazard family entry and the P4 version ledger, which is the split D2 prescribes.
