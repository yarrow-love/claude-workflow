# `reference-gate` — the reference-integrity axis as executable product, and one authoritative home for the sanctioned-absence set

## Refactor Objective

> manager@play/9362ff9f-c270-4704-97cc-14d527ba9f12 # janitor hat

Filed by the phase-4a dogfood hygiene pass as its **rung-2 remedy order** (`janitor.md` § The remedy ladder: "everything above the threshold becomes a typed remedy work order … The Janitor directs; it does not operate"). The pass's full findings and evidence paths are in [`work/todos/26-07-25.prove-pass.md`](26-07-25.prove-pass.md) § Pass Record; the finding IDs below (`A4-4`, `A4-5`, …) index into it.

**This order is filed, not planned.** Per `work/todos/README.md` § Filing, a filing carries the what, the why and the constraints — no investigation and no plan. Session 4b runs it through the normal work-order path from step 1: investigate, plan, **bless**, build, review, gate, close.

### Why this is one order and not several

Four findings share one cause and one cure, and bundling them is what makes the cure *provable in a single diff*:

- The reference-integrity axis is doctrine with no owner — a grep recipe transcribed into `work/PROJECT.md`, which every consuming project must re-author. Charter amendment A1 calls that "prose without an owner", the failure this mission exists to kill.
- The sanctioned-absence set has **three homes** that already disagree, which is exactly the drift the axis is supposed to catch.
- The gate cannot become the axis's owner while the axis's own facts live in the recipe that the gate would replace.

Splitting them would leave a state where BASELINE, the declaration and the gate each hold a partial copy — the manufactured-divergence hazard Reconnaissance R2 warns about, in a new costume.

### 1. The script — `.claude/bin/reference-gate`

A **generic engine with zero project facts**. Every project-shaped input is read from `work/PROJECT.md` § Structure, whose heading strings and bullet grammar are a parser contract pinned in `.claude/BASELINE.md` bootstrap step 3 (Executor ruling 1 — read the contract from its home, never from a private copy):

| Input | Read from |
| --- | --- |
| which prefixes count as a tree reference | § Reference-gate scope roots |
| which containers are skipped | § Reference-gate exclusions |
| which absences are sanctioned | § Sanctioned absences |

Load-bearing behavior to preserve exactly: **`git show <ref>:<path>` expressions are consumed whole** so tag-qualified paths are never extracted as tree references. `work/PROJECT.md` § All roles item 1 states the doctrine — *tag-qualified paths are provenance data, not tree references; the gate checks the tree, tags carry history* — and it must survive the port verbatim in behavior.

House conventions for `.claude/bin/`: bun; no-args prints usage and exits 1. **Hazard**: `.claude/ADR.md` § Standing hazards — a literal `*/` inside the JSDoc header closes the comment early and bun then refuses to parse the file. Keep globs out of header prose; verify with `bun run` after editing the header.

## Constraints

> manager@play/9362ff9f-c270-4704-97cc-14d527ba9f12 # janitor hat

**Genericity is the acceptance test.** Zero project-shaped facts enter `.claude/`. The baseline is **exactly one** grep hit for project facts across `.claude/` — `.claude/BASELINE.md:3`, the canonical-home git URL. A second hit is a failure (campaign baseline, measured at `340cdb1` and re-verified by the 4a pass).

**Do not pre-empt the rung-3 forks.** The 4a pass raised three contestable findings that are **open** and belong to the operator, not to this order:

1. **A4-8 — the canon mixes two irreconcilable link styles.** `.claude/agents/manager/CLAUDE.md` writes file-relative links (`](../janitor.md)`); `.claude/commands/*.md` write repo-root-anchored-without-slash (`](.claude/agents/janitor.md)`). No single resolver satisfies both. **Consequence for this order**: a mechanized *relative-link* check cannot be specified until the style is settled, so relative-link checking is **out of scope** here. Do not pick a style; do not silently normalize links. The plan should note the seam so the check can be added once the fork is answered.
2. **A4-7 — filing an order to `_done/` breaks every `../` link inside it.** Systemic, and `_done/` is never-touch.
3. **A5-5 / divergence B — the footgun-index convention.** Explicitly ruled raised-and-open (D-D). **Do not fix it.**

**Do not rewrite historical documents.** `work/todos/_done/` and `work/proposals/` are never-touch (root `CLAUDE.md`; `work/PROJECT.md` § Documenter). `.claude/ADR.md` is the *living* register and item 5's pointer repairs are in scope — but repair the pointers only, never the determination text.

**The `sessions:` handles above are load-bearing.** `architect@play/5d30e2de-…` is both the consult handle and the **blessing** handle (Reconnaissance R11 — the mission architect is upstream and explicitly *not* the blesser). Reach it with `bun .claude/bin/consult "<handle>" "<question>"`. Verified archived and consultable; the 4a pass also archived the mission-architect transcript, so both handles now resolve.

**Blessing is mandatory and this order has none.** Filing it unblessed is deliberate — 4a files, 4b blesses and executes, and that separation *is* the rung-2 demonstration (Executor ruling 11). 4b writes the `## Blessing` section. In automatic mode an unblessed order past the refinement bound is a terminal `ESCALATE`, not a stage-and-continue (R11).
