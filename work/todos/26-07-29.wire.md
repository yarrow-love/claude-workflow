# Phase 1 — wire: read the event stream, report the cost

## Feature Request

> executor@play/c1378142-cf5c-4ad2-97b0-920533f97a7c

Seeded from [`work/milestones/2.instrumented-consult/1.wire.md`](../milestones/2.instrumented-consult/1.wire.md), which stays the spec and the record — **read it in full before planning**, including its § Hardened at the Reconnaissance gate block. Campaign log: [`26-07-29.execute-m2-instrumented-consult.md`](26-07-29.execute-m2-instrumented-consult.md).

**The objective.** Convert `.claude/bin/consult` from capturing child stdout as an opaque string to parsing a `--output-format stream-json` event wire — extracting the answer and per-consult `usage` — without changing what any existing caller sees on stdout.

**The specification already exists.** `work/milestones/1.spike/1.channel.md` § Addendum maps this wire and names four traps. M2 needs no new measurement; it needs careful implementation against established fact.

**The consult handle.** The last `architect@…` entry above is the milestone architect. It is the same session as the campaign Executor — this milestone was planned and is being executed in one flagship session. Consult it for plan-interpretation questions via `.claude/bin/consult`; genuinely new design decisions escalate.

### The three things most likely to be got wrong

1. **Failure detection, not usage capture, is the hard part.** The current empty-stdout heuristic dies under stream-json. Rekey it on the terminal `result` event — but **probe first**: across M1's whole spike every `result` carried `subtype: "success"`, so the error-subtype branch has no empirical basis, and a bogus `--resume` under stream-json is untested. One throwaway probe, then write the branch against what you saw.
2. **Build the `tool_use_id` → tool-name mapping.** Phase 2's guard depends on it and cannot build its own parser. `tool_result` events carry only the id.
3. **Never touch `permission_denials`.** M1 measured it reporting `[]` across a session that genuinely refused two tools. Reaching for it as a "ran cleanly" signal reproduces the exact defect this milestone exists to fix.

## Acceptance

> executor@play/c1378142-cf5c-4ad2-97b0-920533f97a7c

Carried verbatim from the milestone phase doc.

Headlessly verifiable.

1. **`consult --dry <handle>` prints a command array containing `--output-format stream-json` and `--verbose`**, with `--permission-mode` still last and `--model fable` still present, and exits 0.
2. **A real consult round trip against a small archived handle returns its answer on stdout and nothing else** — stdout captured alone is byte-identical in kind to today's behaviour (answer text, no JSON envelope, no usage line).
3. **The same run emits usage on stderr**, carrying `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, the nested `cache_creation` TTL split, and a cost figure.
4. **`--usage-json` emits one valid JSON object** with those same fields, on stderr, leaving stdout still answer-only. Verified by piping stdout and stderr separately and parsing the latter with `jq`.
5. **Cost is computed as a delta, not the cumulative process total** — evidenced in the code and stated in the work doc, per trap 1.
6. **The four traps are each addressed in code with a comment naming the trap** — an auditor can find all four without reading M1.
7. **Exit codes preserved**: no args → usage on stderr, exit 1; unparseable handle → exit 1; a handle absent from both local cache and archive → exit 3; a handle whose transcript `cwd` is another repo → exit 4. Each demonstrated.
8. **Failure detection no longer rests on empty stdout** — the implementation keys on the terminal `result` event's presence and subtype; stated in the work doc.
9. **The oversized-answer fallback exists, is threshold-driven, and is documented as a fallback**, with the threshold stated.
10. **Genericity** — no repo-specific path, machine name, or project fact enters the script. It would run verbatim in a fresh consuming repo.
11. **Tooling smoke test passes** — `bun .claude/bin/consult` with no args prints usage and exits 1, per `work/PROJECT.md` § All roles.
12. **The `tool_use_id` → tool-name mapping exists and is exposed** for phase 2's guard to consume — gate item 3. Demonstrated by showing the parser resolves a `tool_result` back to the name of the tool that produced it.
13. **The bogus-`--resume` probe ran and its output is recorded** — gate item 4. The failure branch cites what was observed, not what was assumed; if the probe shows an error subtype never occurs, the branch says so rather than coding an unreachable case silently.
14. **`permission_denials` appears nowhere in the phase's code** — gate item 5. Grep-verifiable.
15. **The ENOBUFS path is guarded** — gate item 7, covering both the throw and the status form, with the fail-loud property preserved.
