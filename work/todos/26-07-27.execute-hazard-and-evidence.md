**Diagnosed 26-07-27.** The operator ran the capture command; it returned `Permission denied` on the npx bin. Root cause, measured: the bin symlink's target carries mode `-rw-r--r--` — **no executable bit**. Nothing systemic is at fault — `/home` is btrfs `rw,noatime,…` with no `noexec`, the shebang `#!/usr/bin/env node` is valid, node 22.22.1 resolves — and **every other bin in the same npx cache tree is `-rwxr-xr-x`** (`prettier`, `ctx7`, `figlet`, `bifrost`, `is-docker`, `is-inside-container`); only this package's two bins are affected.

The mechanism is visible in the timestamps: the bin symlink was created **3 Jul**, its target file is dated **14 Jul**. npm applies the exec bit at *bin-link* time; npx reuses its cache directory across runs, and a later in-place refresh rewrote the package contents at default 0644 without re-running bin-linking. Nothing restored the bit. This is why the operator's usual `npm -g` habit does not hit it: a global install re-creates the shim in the global bindir every time.

Recommended fix — a global install, which also removes npx cache-reuse from the launch path of a server Claude Code spawns every session:

```sh
npm i -g chrome-devtools-mcp
claude mcp remove chrome-devtools -s user
claude mcp add chrome-devtools -s user -- chrome-devtools-mcp
```

Alternatives: `rm -rf ~/.npm/_npx/15c61037b1978c83` forces a clean re-fetch on the npx path; a bare `chmod +x` on the target works immediately but can regress on the next refresh, by the same mechanism that produced the fault.

**Left to the operator deliberately** — user-scope MCP config is machine territory (charter D-founding-5) and the campaign's autonomy scope (D-D) excludes installs. The diagnosis is an Executor act; the remedy is not.
