Required content, by section:

- **`## Verifying freshness` (P1, charter D3)** — the known-moved-path query flip (`MATCH (n) WHERE n.file_path CONTAINS '<removed path>' RETURN count(n)` → 0, new path → >0; note **`file_path`, not `path`** — a wrong property name returns empty rows indistinguishable from a clean result, so confirm property names with `keys()`/`properties()` before trusting any negative); the `expected_* == actual_*` gate on every index result (surplus stored-over-expected = stale rows not purged) — state it as a **shape**, not invented field names: every `expected_*` field equals its `actual_*` counterpart; the full-re-index triggers (bulk move/rename, branch switch, binary upgrade, any graph result a file contradicts); the standing rule **when graph and file disagree, the file wins — re-index, then re-ask**; a **three-membered non-signals list** — `head_sha`/`index_status` (frozen at project creation; a badly stale graph can report `head_sha == HEAD`), **node-count parity** (derived edges accrete without garbage collection, so incremental ≠ full even at equal counts, and matching counts are never evidence against a re-index trigger), and **read-only change-detection calls** (tool calls refresh nothing; a change-detection call analyses, it does not re-index); the **serving-session scope** — a verification is evidence only for the server process that performed it, since a session can serve a stale snapshot indefinitely even after a re-index lands; the **declined-watcher staleness cause** (the watcher can refuse work under memory pressure, and a declined re-index is silently stale — the log location routes to the seam); the **restricted query dialect** as phenomenon and defensive posture only (keep queries to the recipe's simple `MATCH`/`WHERE`/`count` shapes, do string surgery outside the query — **no function roster**, that is version-contingent); and the **index-surface conformance audit** (every `File` node under the declared index surface, zero under excluded trees, phrased against the declaration rather than literal paths). That last is **load-bearing**: phase 2's `/initialize` rewrite has nothing read-only to point at without it.
- **`## Recovering a wedged store` (P3)** — the single-process precondition before any store operation or graph-dependent dispatch, with one sentence of rationale: client sessions each spawn their own server against the shared store and a reconnect *adds* rather than replaces, so **never assume a reconnect replaced a server — count processes; the precondition is checked, not inferred**; a symptom list opening the procedure so it is triggerable and not merely executable — a store operation failing on permissions, a re-index no-opping byte-identically, and the `.db-wal` far larger than its `.db` as the wedge canary; the sanctioned recovery — kill all processes → delete `<store-dir>/<project>.db{,-shm,-wal}` → respawn one server → full re-index → verify by the recipe above; and the fact that **no compact/vacuum exists — delete-and-rebuild is the only recovery**. Stated generically: *what* to check and *what* to delete. Per-OS commands and store paths are seam content.
- **`## Evidence-passing dispatch` (P2, charter D4)** — the dispatching role verifies once and the evidence rides the brief: project name, the verification result and **which server session produced it**, qualified symbols, paths, call-chain, coverage. A coverage check's clean result means "**no recorded gap**", never completeness. Specialists treat brief-carried evidence as pre-verified context and **fall back to grep when the brief carries no verification**. On a graph/file contradiction a specialist applies file-wins + grep fallback and **reports** — re-verification and re-index are the dispatcher's acts (architect A7); do **not** prescribe an MCP reconnect. The evidence is recorded where dispatches are already recorded ([`work/todos/README.md`](README.md) § Document structure — the dispatch record); note that section currently carries only the `agentId` convention, so the protocol **extends** it — state the composition concretely, because phase 2's manager-card bullet is written against it.
- **`## The consuming seam`** — what a project records in `work/PROJECT.md`: install variant, store location, per-OS process-check and recovery commands, a known-moved-path candidate for the flip check, and the watcher-log location. State *what* to record, never any project's values.
- **`## Why the graph still comes first` (D6)** — closes the file. Graph-first stands; the protocol adds verification, it does not retreat to grep.
