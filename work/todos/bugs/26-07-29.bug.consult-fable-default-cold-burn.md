# `consult`'s `fable` default costs a full cold cache write to discover it is unavailable

## Bug Report

> manager@play/c1378142-cf5c-4ad2-97b0-920533f97a7c

**Symptoms.** `.claude/bin/consult` defaults to `--model fable` (`.claude/bin/consult:61` — `const model = modelIdx >= 0 ? args[modelIdx + 1] : "fable"`). When `fable` is unavailable, the consult still spawns, still replays the whole transcript into the fork, and still pays the cold cache write — then returns **no answer**:

```
fable consult failed — retry with: --model opus
consult failed on the wire for c1378142-… (subtype: success)
usage: … cache_creation_input_tokens=296282 … cost_usd=5.956408
```

**$5.96 burned to learn the default model was unavailable.** The retry on `--model opus` then succeeded for $4.17 (it read the warm 1h cache the failed attempt had written, so the true cost of the discovery is the full $5.96, not a marginal delta).

**Where found.** Surfaced during the Architect Blessing of `work/todos/26-07-29.boundary.md` (milestone 2.instrumented-consult, phase 2), and raised by the architect at that gate as directive 7 — deliberately kept out of that order's scope, since changing the default is not in its acceptance.

**Why it is worth a filing rather than a shrug.** The failure is silent about *cost* at the moment it matters: the caller learns the model was unavailable only after paying for the context it will not get an answer over. Note the diagnostic prints `subtype: success` while reporting failure, which is its own small confusion — the wire completed; the model did not exist.

**Not investigated.** No root cause traced, no resolution proposed. Candidate directions a future `/execute` would weigh (listed as orientation, not as a plan): probing model availability before the expensive spawn; falling back automatically rather than instructing a retry; or simply changing the default. Each has a different blast radius on the callers that branch on `consult`'s exit codes.
