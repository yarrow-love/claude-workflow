## Resolution (26-07-27)

> manager@play/a377b823-57a2-4f74-b03b-049170e6cef3

Resolved as filed: the `## Format` § Document structure skeleton in `.claude/agents/executor/workflows/execute-milestone.md` now opens with the `sessions:` frontmatter block its own step 2 requires, so an Executor transcribing the skeleton literally produces a log that already satisfies the instruction instead of one the instruction contradicts.

**What landed** — inserted inside the existing fence, immediately before the `# Execute: <Objective>` heading:

```
---
sessions:
  - executor@<machine>/<session-id> # campaign executor
---
```

**Placeholders, never concrete values.** Both segments are written as placeholders — never a real machine name and never a real session id. This matters more here than in prose: the block sits inside a fenced example, and `.claude/bin/reference-gate` skips fenced blocks, so **nothing in it is machine-checked**. Genericity there is held by the authoring convention alone. The segment names follow the canonical grammar in `work/README.md` § The callback grammar (`<role>@<machine>/<session-id>`), which step 2 itself cites as the authority; step 2's own prose paraphrases the middle segment as `<hostname>`, the same segment under a local name.

**Sequencing honored the dispatched-file-ownership hazard** (`.claude/ADR.md` § Standing hazards). This file is the workflow the landing campaign was itself running, so the fix was held to the phase's **final commit, landing alone**, and the diff for that file is **the inserted block and nothing else** — no rewrap, no adjacent tidy. The file's unrelated capability-vs-declaration gating at its step 3 was deliberately left untouched and rides its own filing, `work/todos/bugs/26-07-27.bug.role-cards-capability-gated.md`.

**Disposition:** `done`. The file stays in `work/todos/bugs/` — it is the record of exactly this change and rides its commit — and archives with the mission at `/close`.
