## Reconnaissance

> executor@play/2cb889b5-b570-4b6d-b435-c315de40e68d

Two researchers, one per phase, dispatched synchronously and collected in one turn — the interim campaign practice (the architect's judgment, item 5) applied to this campaign's own first act. Consolidated below; the raw reports are not reproduced.

### Phase 1 — probes: the battery does not yet measure what the doctrine will rest on

**C1 — P1 confounds two variables, and the pre-existing archive already separates them.** *(highest consequence)* P1 instructs `probe-manager-1` to dispatch a background child **and end its turn immediately**, so "dispatched in background" and "dispatcher has stopped" are perfectly correlated in the one arm the probe runs. They are separable. In the M1 campaign's swept subagent archive, a depth-1 Manager dispatched two children with `run_in_background: true` and **stayed alive** (background `Bash` waits) — both completions were delivered as task-notification blocks **into that Manager's own transcript**. The child that did collapse to the root was dispatched `run_in_background: false`, collected synchronously, and stranded only when the Manager later *resumed* it via SendMessage and then stopped. The invariant the evidence favors is therefore **"any completion arriving after the dispatcher has stopped collapses to the root"** — not "background dispatch below the root collapses." P1 as written cannot distinguish the two, and it **cannot reach its own falsifier**: the manager is instructed to stop, so it cannot receive anything. Falsification condition 1 is untestable by P1 as chartered.

**C2 — the recipes' addressing is not executable as written.** The Agent tool has no name parameter; subagent metadata carries `agentType`, `description`, `toolUseId`, `parentAgentId`, `spawnDepth`, `model` — no name. `description: "probe-manager-1"` yields a readable display label but is not addressable. SendMessage addresses by **agentType** (which collides across same-type dispatches — latest wins) or by the **agentId** returned verbatim on every Agent tool result. Recipes must mandate agentId capture at dispatch and address strictly by id; addressing `probe-manager-N` by name fails outright.

**C3 — "foreground — no `run_in_background`" produces a background dispatch.** On a background-default surface (the depth-1 surface observed today on 2.1.220 reads "Subagents run in the background by default… Pass `run_in_background: false` for a synchronous run"), *omitting* the parameter silently turns P2, P3 and P4 into duplicates of P1. Every synchronous arm must pass `run_in_background: false` explicitly, and the parameter must be **verified from the dispatcher's transcript tool-use input**, never from self-report — which closes the filing's own stated caveat (*"'synchronous' is the Manager's self-report. I did not verify the tool-call parameters"*).

**C4 — ledger coverage: two rows uncovered, one of them the row phase 2 stands on.**

| Ledger row | Probe | Coverage |
| --- | --- | --- |
| 1 depth-2 results reach root once dispatcher's turn ended | P1(b) | covered but confounded (C1) |
| 2 a subagent cannot address its parent by name | P3 | partial — name only; by-id and `to: "main"` arms missing |

| 8 notification dropped vs re-routed | P1(b)+(c) | covered *if* read from files: the notification's `<output-file>` path is keyed by the **root** session id even for a depth-2 child |

Row 7 is the gap that matters most. Phase 2's leading doctrine is *fan-out expressed as parallel dispatches collected together in one turn* — and **no probe as written issues more than one dispatch per turn.** Phase 2 would land an idiom the battery never exercised.

**C5 — falsification condition 3 is not a lab probe at all.** "Instances 1/3–6 recurring under strictly synchronous dispatch" cannot be produced in a battery; its evidence is the M1 phase-4 trial already recorded in [`work/notes/26-07-25.child-collection-evidence.md`](../notes/26-07-25.child-collection-evidence.md). Acceptance item 3 requires all three conditions addressed **by name** — so the phase dispositions FC3 by citing that trial, or fails acceptance on a technicality.

**C6 — a forensic arm exists and is strong, and R1 currently excludes it.** The M1 campaign's subagent transcripts (with `spawnDepth` and `parentAgentId` in their metadata) are already swept and archived. Reading them converts several ledger rows from self-report to file-level evidence and supplies the natural experiment behind C1. But R1 states the probe battery is *the only admissible evidence*, so this must be folded in as a named probe to be admissible.

**C7 — mechanics that will bite.** *(a)* `session-archive --from-hook` archives only if `git grep -q <uuid> -- work` matches — **tracked** files: a brand-new untracked work order does not count, so the carrier must be `git add`ed before the probe parent exits. *(b)* The SessionEnd archive lands *after* the session ends, leaving `work/sessions/` dirty with nobody to commit it; `commit-guard` then blocks the next session's first stop. *(c)* If the terminal is killed rather than exited, SessionEnd may not fire — run `bun .claude/bin/session-archive <uuid>` manually as belt-and-braces. *(d)* The CLI is now **2.1.220** at `/home/yarrow/.local/bin/claude`; M1 pinned 2.1.218, so any forensic corpus is from the earlier build and P0 must say so. *(e)* Repo permission default is `bypassPermissions` — a write-capable probe subagent has no backstop but prompt discipline; behavioral probes should run on a low-risk agent type, with `subagent_type: manager` reserved for P5(b) (the surface the filing's claim is actually about). *(f)* `git status --porcelain` before and after is the only detector for a probe child that wrote something. *(g)* The Agent tool is *expected absent* at depth 2 under the cap, so P5(c) should predict absence rather than read it as probe failure.

**C8 — P1's early exit contradicts acceptance item 2.** P1 says the phase "ends early with that verdict"; acceptance requires all five probes carry verdicts. The phase needs a stated rule — early exit settles the doctrine question, but P0 and P2–P5 still record `not run — P1 falsified`.
