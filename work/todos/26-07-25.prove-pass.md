### Fork 1 — divergence B: should the template still model a footgun index the purified `main` does not carry?

**The finding** (A5-5): seven `.claude/` policy documents plus `work/footguns/README.md` instruct every implementer, planner, reviewer, manager and executor to read or reconcile a footgun index in the root `CLAUDE.md`. **Why it is genuinely contestable and not mechanical.** The instructions are *correct as generic convention* — a consuming repo with a populated ledger and a CLAUDE.md index table would be served exactly right by all eight. What broke is specific to this repository: v1's purification (`D4`) emptied the ledger and moved durable hazards into the ADR, and root `CLAUDE.md` was re-authored around the new arrangement while the eight generic instructions kept pointing at the old one. So the tree is not obviously wrong and the canon is not obviously wrong. `janitor.md` § The remedy ladder is explicit that a finding whose remedy is unambiguous but whose *cause* is contested carries that openness as a judgment call.

**Three defensible answers**, none of which the pass may choose:

1. **Restore the convention** — root `CLAUDE.md` (and the template's `CLAUDE.md` guidance) carries a footgun index table again; the eight instructions stand unchanged. Keeps the ledger discoverable by the route eight documents already name; costs a table this repo currently has no entries for.
2. **Retarget the instructions** — the eight say "the ledger in `work/footguns/`, plus the standing hazards in `.claude/ADR.md`", dropping the CLAUDE.md-index presumption. Matches what a purified template actually ships; costs eight edits and loses the per-subsystem index affordance for repos that do want it.
3. **Make it declared** — the ledger's index location becomes a `work/PROJECT.md` fact like every other project-shaped fact, and the generic docs point at the seam. Most consistent with charter D2's engine→product / facts→seam split; the heaviest change, and it adds a supplement question every consuming repo must answer.

**The pass's recommendation: option 2.** It is the only one that makes the shipped template internally consistent *as shipped*, which is the property the mission is about — `main` is the product, and a fresh clone should not carry eight instructions that its own root document does not satisfy. Option 3 is more principled but over-solves: the ledger's location is already fixed convention (`work/footguns/`), and only the *index* is in question. Option 1 restores a table whose sole current content would be a pointer to the ADR.

**Status: raised, open.** Not fixed, per this order's hard constraint and D-D.

### Fork 2 — the canon writes markdown links in two mutually exclusive styles

**The finding** (A4-8). `.claude/agents/manager/CLAUDE.md` writes file-relative links — `](../janitor.md)`, `](workflows/execute-work-order-automatically.md)`. `.claude/commands/*.md` and `.claude/agents/executor/CLAUDE.md` write repo-root-anchored links without a leading slash — `](.claude/agents/janitor.md)`. **The fork**: settle on one style (and normalize under a blessed order), or declare both legal and specify a resolver that tries root-anchored then file-relative. The second is cheaper and tolerant; the first is the only one that makes the canon mean one thing.

**The pass's recommendation: declare root-anchored-without-slash the house style**, because it is what the majority of `.claude/` already does, it is stable under file moves, and it is the only style that survives the `_done/` filing move in fork 3.
