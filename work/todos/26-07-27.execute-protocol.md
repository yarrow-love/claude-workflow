### Content the evidence carries that the phase doc does not require

Recommended into the protocol (the phase doc enumerates required sections, not their full content; these are generic, actionable, and several are load-bearing for phase 2):

1. **The Cypher dialect is restricted** — the verification recipe *is* a Cypher query, and an author unaware of this can write one that errors.
2. **Confirm property names with `keys()`/`properties()` before trusting a negative** — turns the `file_path`-not-`path` caveat from a warning into an action.
3. **The daemon/per-session split** — the singleton applies to the daemon; per-session stdio servers are not deduplicated, and a reconnect *adds* a process. This is the mechanism behind the single-process precondition and behind A7's phrasing.
4. **Wedge symptoms beyond the WAL canary** — a store operation failing on permissions, and a re-index silently no-opping byte-identically. These are what an agent observes first.
5. **Incremental ≠ full re-index even when node counts match** — derived edges accrete without garbage collection, so "counts match, therefore fresh" is unsound. An independent argument for periodic full re-index beyond the four named triggers.
6. **A read-only analysis call is not an index refresh, and tool calls refresh nothing** — a third non-signal, sitting naturally beside `head_sha`/`index_status`.
7. **A declined watcher re-index is a silently stale graph** (the watcher refuses work under memory pressure). Phenomenon in the protocol; log location to the seam.
8. **The index-surface conformance query** — the only read-only observable health check available, and therefore **the thing phase 2 site 6 needs to exist**. Including it in phase 1 unblocks phase 2.

Deferred: a query-hygiene footgun (an unscoped change-detection call emitting ~1 MB of JSON) — real, but it belongs on a role card, not in a freshness/recovery/dispatch protocol.
