## Reconnaissance findings carried in

Established empirically at the gate (bun 1.3.14, this host) — **do not re-probe these, build on them**:

- **`spawnSync` honors `timeout`.** A `sleep 10` bounded at 1000 ms returned at 1006 ms with `status: null`, `signal: "SIGKILL"`, `error.code: "ETIMEDOUT"`. **There is no `status: 143`** — key the `timed_out` branch on `error.code`/`signal`, never on a status number.
- **Detached spawn survives parent exit.** A detached child kept writing for ~6 s after its parent exited. `stdio: "ignore"` is load-bearing, not cosmetic: inherited stdio keeps the parent's event loop alive.
- **`process.kill(pid, 0)`** throws `ESRCH` on a dead pid, silent on a live one. **`fs.openSync(path, "wx")`** throws `EEXIST`. `process.execPath` is the bun binary.
- **`--usage-json` goes to stderr** as its guaranteed-last line, and is emitted **independent of exit code** — see the emission matrix in the phase doc § Telemetry. The rate-limited case emits usage on **exit 3**. Never gate usage parsing on exit 0.
- **`consult:516-526`'s spawn idiom is directly reusable** (the `try`/`catch` *plus* `run?.error` double-check), needing only `timeout`/`killSignal` added.
- **The `rate_limit_events` addition is one line** at the usage-object literal (`consult:391-400`); `renderUsage` spreads that object, so the render site needs no edit and the human-readable line stays byte-identical.
- **Nothing in `.claude/bin/` has ever done detach, locking or liveness** — the daemon mechanics are new territory, de-risked only by the probes above.

## Acceptance

Carried verbatim from the phase doc — the literal convergence target.

1. `.claude/bin/warmth-keeper` exists, is executable, has a bun shebang, and opens with a JSDoc header containing **no literal `*/`** (`.claude/ADR.md` § Standing hazards — a glob written in prose closes the comment and bun then refuses to parse the file). Verify with `bun run .claude/bin/warmth-keeper`.
2. No-arg invocation prints usage and exits 1.
3. All six subcommands are implemented under exactly the names in § The command surface.
4. `register <handle>` creates exactly one file, `~/.claude/warmth/<uuid>.json`; re-registering the same handle does not error and advances `renewedAt`.
5. `release <handle>` unlinks that file and leaves every other handle's file untouched.
6. Grep proves one-file-per-handle: no code path opens a second handle's file for write, and there is no single shared registry file.
7. The four cadence defaults are 58 min / 18 h / 180 s / 3, each overridable by flag, and each carrying a source comment citing its derivation.
8. `tick` exits rather than looping; a handle not yet due is skipped **without spawning `consult`** — verify with a clock override and assert no child was spawned.
9. Beats are issued only through `.claude/bin/consult`. Grep proves the file never spawns `claude` directly.
10. A hung beat returns: with the consult path pointed at a sleep stub exceeding the timeout, `tick` records `timed_out` and completes. Assert `tick`'s own exit is timely and its exit code is 0. The `timed_out` branch keys on `run.error?.code === "ETIMEDOUT"` (or `run.signal != null`) — **grep proves no branch tests for status `143`**.
11. No beat path throws out of `tick`: `run.error`, `run.signal`, and non-zero `run.status` are each handled as returned state. Verify by pointing the consult path at a stub that exits non-zero and one that is missing entirely.
11a. **Usage is parsed on every beat regardless of exit code** — verify with a stub emitting a usage JSON line on stderr while exiting 3: the telemetry record carries both the non-zero exit *and* the parsed usage object. Grep proves no `exitCode === 0` guard gates usage parsing.
12. A failing beat is **never retried inside the window** — assert exactly one `consult` spawn per due handle per `tick`, whatever the outcome.
13. Telemetry is appended as JSONL with the fields listed in § Telemetry, one object per beat, and every object parses.
14. `consult --usage-json` emits `rate_limit_events` as a number; all previously-emitted keys are byte-identical on an unchanged consult. No other `consult` behavior is modified — verify by diffing the file and confirming the change is confined to the usage-object construction.
15. Concurrent invocation is guarded: a second `tick` while one holds the lock exits without beating. A lock whose owner is dead, or whose heartbeat exceeds 3× the beat interval, is reaped and taken over.
15a. **`register` takes the same lock** before deciding start-vs-attach, so two near-simultaneous registrations cannot both spawn a daemon. Verify by racing two `register` calls and asserting exactly one daemon pid results.
16. `register` starts the daemon when absent and attaches when present; the daemon survives the parent's exit (verify: register, let the invoking shell exit, confirm the pid is still live and the heartbeat advances).
17. Releasing the last handle causes a running daemon to exit within one beat interval.
18. **Smoke test — the milestone's warmth evidence.** Register a **small archived handle** (never the 6 MB vehicle) with `--interval 60s`; observe **≥2 beats** in the telemetry; confirm beat #2 shows `cache_read_input_tokens > 0` and `cache_creation_input_tokens ≈ 0`.
