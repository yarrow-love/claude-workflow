# Phase 2 — boundary: close the false clean sheet

## Feature Request

> executor@play/c1378142-cf5c-4ad2-97b0-920533f97a7c

Seeded from [`work/milestones/2.instrumented-consult/2.boundary.md`](../milestones/2.instrumented-consult/2.boundary.md) — **read it in full**, including both its § Hardened at the Reconnaissance gate block and its § Added at the phase-1 gate block. Campaign log: [`26-07-29.execute-m2-instrumented-consult.md`](26-07-29.execute-m2-instrumented-consult.md).

**The objective.** Reconcile `consult`'s DENY list against v2.1.220, and turn M1's `permission_denials` trap into an enforced invariant using the parser phase 1 built.

**Phase 1 landed and its handoff is verified.** `parseWire()` returns `toolNames: Map<tool_use_id, name>` and `toolResults[]` with the name already resolved through the join (`.claude/bin/consult:298–333`). **Consume it. Do not build a second parser** — acceptance item 6 makes that binding.

### The three things most likely to be got wrong

1. **The guard must run before every exit path, including `degrade()`.** This is not hypothetical: phase 1's review found the usage render sitting *after* every `degrade()` call site, so a consult that burned tokens and then failed reported no cost. The guard has the identical shape, and a silent boundary violation is strictly worse than a silent cost — the guard **is** D5's enforcement, so an exit path that skips it makes the boundary enforced only where nothing went wrong. Route exits through **one finalizer**; do not fix it by ordering call sites, which re-creates the bug at the next exit path added.
2. **The predicate is a conjunction, and the name comes from the join.** Name outside `{Read, Grep, Glob}` **and** `is_error` falsy (absent *or* false). A `tool_result` does not carry a tool name — only `tool_use_id`.
3. **Scan every `tool_result`, never the terminal `result` event.** Its one candidate rollup field is `permission_denials`, the exact signal this phase exists to stop trusting.

### Inherited corrections from phase 1

- **ENOBUFS does not throw** on bun 1.3.14 — `spawnSync` returns with `run.error` set and `status: 143`. Failure arrives through normal control flow, so a try/catch-shaped guard placement misses the real failure shape. The `violation-truncated` fixture covers this.
- **The wire carries a `rate_limit_event` type** M1 never enumerated, which is why the parser deliberately does not switch exhaustively on `type`. Preserve that posture.

## Implementation Plan

> manager@play/c1378142-cf5c-4ad2-97b0-920533f97a7c

Five phases. The dependency spine is that phases 2 and 4 edit overlapping regions of one 474-line file and must be sequential — carried by **one implementer**, two commits; phase 3 is disjoint (new files only) and runs in parallel.

```
1 (Cd probe, no edits) ──► 2 (DENY + pin) ──► 4 (guard + finalizer) ──┐
                                                                      ├──► 5 (verify)
3 (fixtures + runner) ────────────────────────────────────────────────┘
```

**Phase 1 — probe `Cd`.** Read-only, no edits. Render `consult`'s command array via `--dry` against the smallest local handle, then run that array verbatim with stdout teed to `tmp/spike/`, so the probe sees the raw wire rather than `consult`'s filtered stdout while guaranteeing the identical five-layer construction. The fork is asked to `ToolSearch` for `Cd` and invoke it; the same prompt corroborates the three confirmed DENY names for free. **The discriminant is read off the wire, never off the model's prose**: M1's real refusal text (`"…exists but is not enabled in this context…"`) is the control string already on disk. Four distinguishable shapes — absent from the registry; callable and succeeding; refused with the *generic* text (deny-by-name governs it); refused with a *distinct* text (the `cdRuleRefusalMessage` family — gate ruling 10's third shape, recorded as-is).

**Phase 2 — DENY reconciliation.** Three names added to their existing sibling groups; header pin `2.1.197` → `2.1.220`; `Cd` added or its rejection recorded per phase 1's verdict. `.claude/ADR.md` deliberately untouched (D6). Smoke-test immediately after the header edit — the standing `*/`-in-JSDoc hazard makes bun refuse the whole file.

**Phase 3 — fixtures + runner** under `work/milestones/2.instrumented-consult/fixtures/`. Four `.jsonl` fixtures plus a README provenance ledger recording which lines are verbatim M1 seed and which are synthesised. `clean` and `refused` are trimmed from the real seed (including the verbatim `<tool_use_error>` bytes); `violation` and `violation-truncated` are synthesised. The violation fixture omits `is_error` **entirely** rather than setting it false — that is what exercises the *absent* arm of the conjunction. The truncated fixture cuts mid-way through the next event's JSON, so it also carries one unparseable line.

The runner drives the **real** `.claude/bin/consult` as a subprocess with a stub `claude` on `PATH` inside a hermetic sandbox (temp `HOME`, temp git repo, temp transcript with the slug computed exactly as `consult` computes it). No test seam enters production tooling, no network call is made, and the assertions land on the shipped parser, guard, finalizer, exit codes and stdout/stderr separation. Phase 1's verification already used stub-`claude` runs for three of its criteria — this generalizes that precedent into committed apparatus.

**Phase 4 — the guard and the single finalizer.** A hoisted `function finish(code)` sited above argument parsing, reading a module-level `wire` that is null until the parser runs; **all eight** `process.exit` sites re-route through it, including `degrade()`'s tail. `degrade()` loses its wire parameter outright — behaviour-preserving, because the module `wire` is assigned at exactly the point the old parameter began being passed, and leaving the parameter is how per-call-site discipline creeps back. The predicate filters `toolResults[]` for error-free entries whose resolved name is outside `{Read, Grep, Glob}`; phase 1's parser already normalizes absent-vs-false `is_error` to one value, so the conjunction is complete by construction. Exit 5 joins the header ladder and `work/PROJECT.md`'s smoke-test description in the same commit as the guard.

**Phase 5 — verification.** The runner's four cases; `grep -c process.exit` → 1; `grep -c permission_denials` → 0 (comments included — this phase writes comments about exactly that field); `git diff --stat` showing `.claude/ADR.md` absent; the pin reading `2.1.220`. The two carve-outs stand: the 9 pre-existing `herdr.md` reference-gate failures (already filed, verified byte-identical against HEAD) and `/initialize` not being headlessly invocable (deferred to the milestone close, as phase 1 did).
