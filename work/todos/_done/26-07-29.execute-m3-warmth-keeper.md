A keeper reading usage only on exit 0 would discard exactly the records charter criterion 5's enumerability rests on. The phase doc now carries the full emission matrix and a criterion forbidding an exit-code guard.

### Risks and decisions settled by the Executor

**The orphaned grandchild is accepted, not engineered around.** Killing a timed-out `consult` leaves its `claude` grandchild reparented to init, since `consult` spawns it synchronously with no timeout of its own. Tolerable and bounded: a `-p` turn always terminates, the tokens were committed when the beat fired, and `maxConsecutiveFailures` lapses a chronically-timing-out handle. Process-group kill would need a POSIX/Windows branch and buy nothing.

**`register` takes the tick lock** before deciding start-vs-attach — the spec's lock criterion was tick-scoped only, leaving two near-simultaneous registrations able to spawn two daemons.

**Vocabulary collision, three ways.** "Registry" now names three unrelated things (the ADR *decision register*, `work/README.md` § Machine registry, the keeper's per-handle store), "daemon" already names the codebase-graph coordination daemon, and "the scheduler" is `integrator.md`'s undefined merge-queue actor. Phase 2 forbids all three bare forms.

**The registration convention becomes a `###` subsection**, mirroring § Machine registry — five substantial points do not belong crammed into an already-dense bullet list.

### Findings that strengthen the plan

**Every daemon mechanic probed clean on bun 1.3.14.** Detached spawn survives parent exit (heartbeat kept growing ~6 s after the parent exited); `process.kill(pid, 0)` throws `ESRCH` on a dead pid and is silent on a live one; `fs.openSync(path, "wx")` throws `EEXIST`. `process.execPath` resolves to the bun binary. Context7 adds the reason `stdio: "ignore"` is load-bearing rather than cosmetic: inherited stdio keeps the parent's event loop alive.

**The `rate_limit_events` addition really is one line.** The events array is in scope where the usage object is built (`consult:391-400`), and `renderUsage` spreads that object into the JSON — so the field flows through with no edit at the render site, and the human-readable line (which hand-lists fields) stays byte-identical. Criterion 14's "previously-emitted keys byte-identical" is achievable with a genuinely single-field diff.

**`consult:516-526`'s spawn idiom is directly reusable** — the `try`/`catch` *plus* `run?.error` double-check the keeper needs, requiring only `timeout`/`killSignal` added. Nothing in `.claude/bin/` has ever done detach, locking or liveness, so the daemon mechanics are new territory — but the probes above de-risk each one individually.

**No blockers elsewhere.** Footgun ledger genuinely empty; the Windows `claude.exe` drift hazard the milestone cites is a real, citable passage; the nine-failure `reference-gate` baseline confirmed independently.
