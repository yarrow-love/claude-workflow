## Feature Request

Campaign log: [`26-07-28.execute-m1-spike.md`](26-07-28.execute-m1-spike.md).

**The objective.** Establish empirically whether a held-open `claude -p --input-format stream-json --output-format stream-json` process against a real large session is (a) a *session* — capturable id, live-appending transcript, resumable after its process dies — (b) an *observable* one, emitting a usable per-turn event wire, and (c) a *bounded* one, able to answer consults without acquiring the ability to act.

**This phase can end the mission, and that is a success.** It carries both of mission v4's refutation-shaped failure criteria. If live transcript append, the event wire, or the read-only boundary cannot be demonstrated, **stop and escalate with the refuting evidence** — do not engineer around it. A refutation here is a completed phase, not a failed one.

**The consult handle.** The last `architect@…` entry above is the milestone architect. Note that it is the same session as the campaign Executor — an artefact of this milestone being planned and executed in one flagship session. Consult it for plan-interpretation questions via `.claude/bin/consult`; genuinely new design decisions still escalate.

### Confirmed decisions — settled at the Reconnaissance gate, not open for re-litigation

These were fixed after two researcher passes found four defects in the phase doc as first written. The doc has been amended to carry them; they are restated here because they are the ones most likely to be silently re-invented.

1. **The vehicle is passed as an explicit argument** — `76ba13c6-e6f5-4933-9e6c-7ef3fbdd6b7d` (6,456,439 bytes, `cwd` verified as this repo). The harness must **not** auto-select "the largest transcript": no documented mechanism exposes a session's own id to a script it invokes, so the exclusion could not be implemented safely and a buggy one could fork the hosting session's live transcript. If the vehicle is absent at run time, escalate — never substitute a trivial session.
2. **`--fork-session` is mandatory.** Without it, resume mutates a real recorded session in place. The spike never writes into a transcript it did not create.
3. **Pin `--model fable` explicitly on every spawn.** It is *not* one of `consult`'s five read-only layers — it is a separate flag, defaulted there — so "reproduce the five layers" leaves it unset. The prompt cache keys on the byte-exact prefix and system-prompt content varies with model; an unpinned model would invalidate phase 2's entire matrix.
4. **Harness topology: a channel primitive + a driver**, not a monolith — phase 2 extends this with a matrix driver and a fork-measurement path.
5. **Bun `spawn` mechanics** (bun 1.3.14; all four existing `.claude/bin/` scripts are `spawnSync`, so there is no in-repo precedent): `stdin` is a `FileSink`, so **`.write()` must be followed by `.flush()`** per turn or turn N+1 silently never arrives; **EOF comes from `proc.stdin.end()`, never `proc.kill()`**; and **stdout *and* stderr must be drained concurrently** with the exit promise or the OS pipe buffer deadlocks.
6. **Discovery is two-stage.** Observe the turn-completion signal on turn 1 before driving turns 2–3 automatically; "discover and use" is not one step.
7. **Trivial canned turns** for the ≥3-turn demonstration; boundary probes ride the *same* channel as turns N+1/N+2, demarcated in the run log so refusal turns are never folded into the wire-format evidence.
8. **Artifacts**: harness → `work/milestones/1.spike/harness/` (tracked, archives with the mission); raw stream logs → `tmp/spike/` (gitignored, declared in `work/PROJECT.md` § Structure). **Nothing lands under `.claude/`** — no `consult` edits, no new bin script, no BASELINE amendment. Record, do not repair, any DENY-list drift found.

### What phase 2 needs from this phase

Its matrix design depends on criterion 5's answer about where `usage` rides. If per-turn `usage` is **not** emitted inside a multi-turn streaming process, say so plainly and prominently — phase 2 must then restructure to one process per measured turn, which weakens the very comparison the spike exists to make. Criterion 12's last-touch timestamp is the clock phase 2's cold baseline depends on.

## Implementation Plan

> manager@play/c1378142-cf5c-4ad2-97b0-920533f97a7c

### Approach

Two bun files under `work/milestones/1.spike/harness/`: a **channel primitive** (`channel.ts`) owning the spawn construction, the stdin FileSink discipline, the concurrent stdout/stderr pumps with tee-before-parse, and an event queue; and a **driver** (`spike-run.ts`) owning preflight, turn choreography, transcript sampling, the structured run log, and teardown. Phase boundaries fall where unknowns resolve, so a surprising answer reshapes only downstream phases: the scaffold is buildable and dry-run-verifiable with **zero API calls** (A); the stdin wire shape and turn-completion signal are unknown until one real turn is observed (B — discovery stage 1); only then can turns 2–3, the pre-exit samples, and the boundary probes be driven automatically (C — stage 2); clean-death evidence completes only after the process is dead (D); the evidence write-up runs last because criteria 12 and 13 are only final after D (E).

**All three charter-failure gates (criteria 4, 5, 7) are evaluated inside phase C.** A failure there truncates D to whatever teardown evidence exists and turns E into the refutation record — a successful phase outcome, not a failed one.

### Phases

**A — Scaffold, preflight, dry-run; DENY-drift audit.** No dependencies. Creates `harness/channel.ts`, `harness/spike-run.ts`, `harness/README.md`.

- `channel.ts` exports `openChannel(opts)` → `{ pid, sendTurn(text), nextEvent(), waitFor(predicate, timeoutMs), end(), exited, rawLogPath }`. Command array mirrors `.claude/bin/consult` verbatim plus the streaming deltas: `--resume <vehicleId> --fork-session --model fable --settings <json> --strict-mcp-config --mcp-config '{"mcpServers":{}}' --allowedTools Read,Grep,Glob --disallowedTools <DENY> --permission-mode dontAsk --verbose --input-format stream-json --output-format stream-json`. No positional prompt — turns ride stdin. DENY array **copied verbatim** from `consult`, header-commented with copy date + source commit. Settings JSON carries `permissions: { defaultMode: "dontAsk", deny: DENY }` **and** `disableAllHooks: true`.
- **Both pump loops start at spawn, before any write** — structurally prior to any `await exited`. stdout appends raw bytes to `rawLogPath` *before* newline-split + `JSON.parse`; parse failures logged, never fatal. stderr tees to a sibling `.stderr.log`.
- `sendTurn` couples `write(json + "\n")` with `flush()` unconditionally. `end()` is `proc.stdin.end()` only; the sole kill path is `proc.kill()` on the exact captured handle, last-resort, recorded as unclean. No `pkill`/`killall`/name-match anywhere.
- `spike-run.ts`: `#!/usr/bin/env bun`, `repoRoot` via `git rev-parse --show-toplevel`, slug derivation as in `consult`. No args → `usage:` to stderr, exit 1. Usage `bun work/milestones/1.spike/harness/spike-run.ts <vehicle-uuid> [--observe] [--dry]`. Preflight: vehicle transcript must exist and its recorded `cwd` must match `repoRoot` — **absent means escalate and exit non-zero, never substitute**. `--dry` prints the command array and exits 0.

### Risk register

| Failure mode | Silent symptom | Mitigation (phase) |
| --- | --- | --- |
| OS pipe-buffer deadlock | `--verbose` + stderr warnings fill an undrained pipe; child stalls, looks like a slow model | both pumps start at spawn, structurally prior to any `await exited` (A) |
| Missing `flush()` | turn 1 works, turn 2 never arrives; looks like a model stall | `sendTurn` couples write+flush unconditionally; B verifies arrival (A, B) |
| Sampling at the wrong moment | both samples land after exit, or before turn 1's append — criterion 4 evidence void or falsely refuting | samples keyed to `TURN_END`, liveness asserted and recorded, bounded ≤5 s re-poll before declaring no-growth (C) |
| Hooks fire inside the read-only child | `SessionEnd`/`Stop` mutate the tree or block exit | `disableAllHooks: true` (A); post-run inspection naming commit-guard as the hang candidate (D) |
| Child never exits on EOF | driver awaits forever, or a reflexive kill destroys clean-death evidence | EOF exclusively via `stdin.end()`; bounded 60 s; last-resort kill on the exact handle only, recorded as unclean (C) |
| Forking the wrong transcript | auto-selection forks the hosting session's live transcript | explicit vehicle argument + existence/cwd preflight; absent = escalate (A) |
| Parse failure destroys evidence | a stray non-JSON line aborts the reader, run's events lost | raw bytes teed before any parse; parse errors non-fatal (A) |
| Wire shape confounded | two candidates down one stdin, can't attribute | one fresh spawn per candidate (B) |
| Under-stated last-touch clock | probe-2's stamp reported while D's resume re-warms the prefix afterwards | last-touch = max over all API calls, taken at D (D, E) |
| Manufactured DENY drift | cosmetic "matches no known tool" warning read as drift | criterion-14 language baked into the audit output (A) |
| Events-only-at-exit misread | terminal blob looks like "signal not found yet" and gets retried forever | observe-mode timeout + EOF makes buffering visible; that log *is* the criterion-5 refuting evidence (B/C) |
